# المرحلة 4: تحليل الشبكة وبناء الحزم

## لماذا تهم هذه المرحلة

تقريبًا كل نشاط أمني يلمس الشبكة في النهاية. الاستطلاع والاستغلال والتحكم والقيادة وحركة البيانات والكشف الدفاعي كلها تترك آثارًا في الحزم. لذلك فإن القدرة على التقاط حركة الشبكة وقراءتها وتفسيرها من أعلى المهارات العملية تأثيرًا التي يمكنك تطويرها.

المرحلة 0 والمرحلة 1 منحتاك النماذج المفاهيمية (OSI وTCP/IP والبروتوكولات الشائعة).  
هذه المرحلة تمنحك القدرة العملية على *رؤية* تلك الحركة وبناء حزم بسيطة داخل المختبر لأغراض التعلم.

---

## أهداف التعلم

بنهاية هذه المرحلة ستكون قادرًا على:

- التقاط الحركة الحية وحفظها في ملفات PCAP باستخدام Wireshark وtshark
- فتح ملفات PCAP والتنقل فيها بثقة
- تطبيق مرشحات العرض والتقاط للبروتوكولات الشائعة
- تحديد الحقول الرئيسية لحزم Ethernet وIP وTCP وUDP وDNS
- استخدام Scapy لفحص الحزم الأساسي والبناء المنضبط داخل المختبر
- ربط الحركة المرصودة بالعمليات والخدمات التي فحصتها في المراحل السابقة
- اتباع قواعد سلامة صارمة حتى لا تغادر عملية بناء الحزم المختبر أبدًا

---

## نقطة التحقق الأمني

**التقاط الحزم** آمن عمومًا عند تنفيذه على واجهات تتحكم بها.  
**بناء الحزم وحقنها** يجب أن يقتصر على شبكات المختبر التي تملكها.

لا تحقن حزمًا مبنية على شبكة إنتاج أو الإنترنت العام أبدًا.  
لا تلتقط حركة على شبكات ليس لديك تفويض لها.

جميع الأمثلة أدناه تفترض أنك تعمل داخل المختبر المعزول الذي أنشأته في المرحلة 1.

## 1. دور تحليل الشبكة

يجيب تحليل الشبكة على أسئلة مثل:

- من يتحدث إلى من؟
- ما البروتوكولات والمنافذ المستخدمة؟
- هل هناك اتصالات غير متوقعة أو بيانات اعتماد بنص واضح؟
- هل تتطابق الحركة مع ما يجب أن يفعله التطبيق أو الخدمة؟
- هل يمكنني إعادة بناء محادثة (مثل طلب/استجابة HTTP)؟

يستخدم المدافعون نفس المهارات للكشف والاستجابة للحوادث. ويستخدمها المهاجمون (في الاختبارات المصرح بها) لفهم البيئة. تعلم كلا المنظورين يجعلك أقوى في أي جانب.

---

## 2. Wireshark وtshark

**Wireshark** هو المعيار الرسومي لتحليل الحزم.  
**tshark** هو نظيره في سطر الأوامر — مثالي للبرمجة النصية والبيئات البعيدة أو بدون واجهة رسومية.

### سير عمل التقاط أساسي (مفاهيمي)

1. اختر واجهة الشبكة الصحيحة (واجهة المختبر التي يمكنها رؤية الحركة محل الاهتمام).
2. ابدأ التقاطًا.
3. ولّد الحركة التي تريد دراستها (تصفح تطبيق ويب مختبري، أو نفّذ مسحًا مختبريًا، إلخ).
4. أوقف التقاط واحفظه كملف PCAP/PCAPNG.
5. طبّق مرشحات العرض للتركيز على الحزم المثيرة للاهتمام.

### أمثلة tshark مفيدة (المختبر فقط)

```bash
# سرد الواجهات
tshark -D

# التقاط على واجهة محددة لمدة 30 ثانية
tshark -i eth0 -a duration:30 -w lab_capture.pcap

# قراءة PCAP موجود وعرض ملخص قصير
tshark -r lab_capture.pcap -c 20

# مثال على مرشح عرض: DNS فقط
tshark -r lab_capture.pcap -Y "dns"
```

## 3. مرشحات العرض التي ستستخدمها باستمرار

تتيح لك مرشحات عرض Wireshark/tshark إخفاء الضوضاء والاحتفاظ بالإشارة.

| المرشح | المعنى |
|--------|--------|
| `dns` | حركة DNS |
| `http` | حركة HTTP |
| `tcp.port == 80` | منفذ TCP 80 |
| `ip.addr == 192.168.56.10` | حركة من أو إلى مضيف محدد |
| `tcp.flags.syn == 1 && tcp.flags.ack == 0` | حزم SYN (بداية مصافحة TCP) |
| `http.request` | طلبات HTTP فقط |
| `frame contains "password"` | إطارات تحتوي على السلسلة (استخدم بحذر) |

تعلّم بضعة مرشحات جيدًا بدلاً من محاولة حفظ العشرات. منشئ التعبيرات في Wireshark والوثائق الرسمية مراجع ممتازة.

## 4. قراءة رؤوس البروتوكولات الشائعة

عند فتح حزمة، تدرب على تحديد:

**Ethernet**
- عناوين MAC المصدر والوجهة

**IP**
- عناوين IP المصدر والوجهة
- رقم البروتوكول (6 = TCP، 17 = UDP، 1 = ICMP)

**TCP**
- منافذ المصدر والوجهة
- أرقام التسلسل والتأكيد
- الأعلام (SYN وACK وFIN وRST وPSH وURG)
- حجم النافذة

**UDP**
- منافذ المصدر والوجهة
- الطول

**DNS**
- اسم الاستعلام
- نوع الاستعلام (A وAAAA وMX وغيرها)
- رموز الاستجابة والإجابات

لا تحتاج إلى حفظ كل حقل. الهدف هو القدرة على الإجابة على "من يتحدث، على أي منافذ، وما الغرض عالي المستوى لهذه المحادثة؟"

## 5. Scapy للفحص والبناء المنضبط

Scapy مكتبة Python قوية لمعالجة الحزم. يحتوي المشروع بالفعل على عدة سكربتات Scapy تعليمية تحت `Codes/Python/04_network_analysis/`. تعلّمك هذه المرحلة العقلية لاستخدامها بأمان.

### قراءة الحزم

```python
from scapy.all import rdpcap, sniff

packets = rdpcap("lab_capture.pcap")
packets[0].show()          # عرض مفصل للحزمة الأولى
packets[0].summary()       # ملخص بسطر واحد
```

### التقاط بسيط (واجهة المختبر فقط)

```python
from scapy.all import sniff

pkts = sniff(iface="eth0", filter="udp port 53", count=5)
pkts.summary()
```

### بناء منضبط (أهداف المختبر فقط)

البناء مفيد لفهم كيفية عمل البروتوكولات واختبار كيفية تفاعل خدمة مختبرية. قصِر دائمًا عناوين الوجهة على أنظمة داخل مختبرك.

مثال مفاهيمي (استعلام DNS إلى محلل مختبري أو محلل عام من جهاز الهجوم فقط للتعلم):

```python
from scapy.all import IP, UDP, DNS, DNSQR, sr1

packet = IP(dst="8.8.8.8")/UDP(dport=53)/DNS(rd=1, qd=DNSQR(qname="example.com"))
response = sr1(packet, timeout=2)
if response:
    response.show()
```

**قاعدة سلامة:** إذا احتوى سكربت Scapy على عنوان IP وجهة، تحقق أن هذا العنوان ينتمي إلى جهاز تملكه أو لديك إذن صريح باختباره قبل تشغيله.

## 6. ربط الحزم بالمضيفين والعمليات

يصبح تحليل الشبكة أقوى بكثير عند دمجه مع مهارات المضيف من المرحلتين 2 و3:

- على المضيف: `ss -tulnp` أو `Get-NetTCPConnection` يظهر أي عملية تملك منفذًا.
- في ملف PCAP: ترى الحزم الفعلية التي ترسلها وتستقبلها تلك العملية.
- معًا يمكنك الإجابة على "فتحت هذه العملية ذلك الاتصال ونقلت هذه البيانات."

هذا الربط تقنية أساسية لكل من الاستجابة للحوادث والاختبار المصرح به.

## 7. سير عمل تحليل شائعة في المختبر

**سير العمل أ — فهم طلب ويب**
1. ابدأ التقاطًا على واجهة المهاجم أو الهدف.
2. تصفح تطبيق ويب مختبري (DVWA أو Juice Shop وغيرها).
3. أوقف التقاط.
4. رشّح على `http` أو منفذ TCP ذي الصلة.
5. اتبع تدفق TCP لرؤية الطلب والاستجابة المعاد بناؤهما.

**سير العمل ب — مراقبة حل الأسماء**
1. التقط الحركة.
2. ولّد نشاط DNS (زر موقعًا، أو استخدم `dig` أو `nslookup` ضد محلل مختبري أو عام).
3. رشّح على `dns` وافحص الاستعلامات والإجابات.

**سير العمل ج — رسم خريطة المحادثات**
1. افتح ملف PCAP.
2. استخدم Statistics → Conversations (في Wireshark) أو خيارات المحادثة في tshark.
3. حدد أكثر المتحدثين والمنافذ التي يستخدمونها.

## أخطاء شائعة

| الخطأ | العاقبة | الممارسة الأفضل |
|-------|---------|-----------------|
| التقاط على الواجهة الخاطئة | ملف PCAP فارغ أو غير ذي صلة | أكد الواجهة بـ `ip addr` / `tshark -D` أولاً |
| التقاط دون مرشح على شبكة مزدحمة | ملفات ضخمة وصعبة التحليل | ابدأ بمرشح التقاط عند الإمكان |
| حقن حزم مبنية خارج المختبر | مخاطر قانونية وتشغيلية | قصِر الوجهات على عناوين IP المختبر فقط |
| النظر فقط إلى قائمة الحزم دون متابعة التدفقات | تفويت محتوى مستوى التطبيق | استخدم "Follow TCP Stream" بانتظام |
| افتراض أن البروتوكولات بنص واضح نادرة | تفويت بيانات اعتماد أو بيانات حساسة | تحقق دائمًا من HTTP وFTP وTelnet وغيرها في حركة المختبر |

1. ما الفرق بين مرشح التقاط ومرشح عرض؟

6. أعطِ سببًا عمليًا واحدًا لتفضيل tshark على Wireshark في مواقف معينة.
