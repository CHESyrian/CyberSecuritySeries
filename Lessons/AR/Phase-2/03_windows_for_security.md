# المرحلة 3: Windows لممارسي الأمن

## لماذا تهم هذه المرحلة

تعمل العديد من المؤسسات على مزيج من أنظمة Windows وLinux. محطات عمل المستخدمين النهائيين ونطاقات Active Directory وخوادم الملفات والعديد من تطبيقات الأعمال تعتمد على Windows. ممارس الأمن الذي يستطيع العمل على Linux فقط مجهز بنصف الأدوات.

المرحلة 0 قدّمت مفاهيم Windows (الهندسة، صلاحيات NTFS، الخدمات، العمليات، السجل، عارض الأحداث، PowerShell، Active Directory).  
هذه المرحلة تحول تلك الأفكار إلى عادات تحقيق عملية يمكنك استخدامها داخل المختبر أو لاحقًا في المهام المهنية المصرح بها.

---

## أهداف التعلم

بنهاية هذه المرحلة ستكون قادرًا على:

- استخدام PowerShell كواجهة التحقيق الأساسية
- سرد العمليات والخدمات واتصالات الشبكة على نظام Windows
- قراءة سجلات أحداث Windows وتصفيتها للأحداث الأمنية المهمة
- فحص مواقع السجل الأساسية التي تؤثر على الوضع الأمني
- فهم مفاهيم المستخدمين المحليين والمجموعات والامتيازات
- تطبيق نفس عقلية أقل الامتيازات التي مارستها على Linux
- توثيق النتائج بوضوح لإعداد التقارير لاحقًا

---

## نقطة التحقق الأمني

جميع الأوامر والتقنيات في هذه المرحلة مخصصة لـ**أجهزة Windows الافتراضية التي تملكها وتتحكم بها** داخل مختبرك المعزول.  
لا تشغّل أوامر تحقيق ضد أنظمة إنتاج أو أي جهاز خارج مختبرك دون تفويض صريح.

---

## 1. PowerShell كوحدة تحكم التحقيق

PowerShell هي بيئة سطر الأوامر والبرمجة النصية الحديثة لـ Windows. يمكن إجراء معظم الفحص الأمني ذي الصلة من خلالها.

عادات مفيدة:

- شغّل PowerShell كمستخدم عادي افتراضيًا؛ ارتقِ فقط عند الضرورة.
- استخدم `Get-Help <cmdlet> -Examples` لرؤية أنماط الاستخدام.
- فضّل أسماء cmdlet الكاملة أثناء التعلم (`Get-Process` بدلاً من `gps`).
- مرّر الناتج إلى `Format-List` أو `Format-Table` أو `Select-Object` لسهولة القراءة.

أوامر توجيه أساسية:

```powershell
$PSVersionTable          # إصدار PowerShell
whoami                   # المستخدم الحالي
whoami /groups           # عضويات المجموعات
hostname                 # اسم الجهاز
Get-Location             # المجلد الحالي
```

---

## 2. العمليات والخدمات

### العمليات

```powershell
Get-Process
Get-Process | Sort-Object CPU -Descending | Select-Object -First 10
Get-Process -Name explorer | Format-List *
```

خصائص مهمة يجب ملاحظتها: اسم العملية، المعرف (Id)، استخدام المعالج والذاكرة، وسياق المستخدم عند توفره.

### الخدمات

```powershell
Get-Service
Get-Service | Where-Object {$_.Status -eq "Running"}
Get-Service -Name "Spooler" | Format-List *
```

الخدمات التي تبدأ تلقائيًا وتستمع على الشبكة تشكّل جزءًا من سطح هجوم النظام. في المختبر يمكنك استكشاف الخدمات العاملة والحسابات التي تستخدمها بأمان.

---

## 3. اتصالات الشبكة والمنافذ المستمعة

يوفر Windows الحديث cmdlets شبكية مفيدة:

```powershell
Get-NetTCPConnection
Get-NetTCPConnection -State Listen
Get-NetTCPConnection -State Listen | Select-Object LocalAddress, LocalPort, OwningProcess
Get-NetUDPEndpoint
```

لربط منفذ مستمع بعملية:

```powershell
Get-Process -Id <OwningProcess>
```

بدلاً من ذلك، لا تزال الأداة الكلاسيكية `netstat` متاحة:

```powershell
netstat -ano
netstat -ano | findstr LISTENING
```

**قراءة الناتج:**  
انتبه لما إذا كانت الخدمة تستمع على `0.0.0.0` (جميع الواجهات) أو `127.0.0.1` (localhost فقط). هذا التمييز مهم لتقييم التعرض، تمامًا كما كان على Linux.

---

## 4. سجلات أحداث Windows

يسجّل Windows حجمًا كبيرًا من الأحداث. السجلات الأكثر أهمية أمنيًا عادة هي:

- Security
- System
- Application
- سجلات PowerShell التشغيلية (عند تفعيلها)

عرض السجلات باستخدام PowerShell:

```powershell
Get-EventLog -LogName Security -Newest 20
Get-WinEvent -LogName Security -MaxEvents 20
Get-WinEvent -FilterHashtable @{LogName='Security'; ID=4624} -MaxEvents 10
```

معرفات أحداث أمنية شائعة تستحق التعرف عليها (وعي مفاهيمي):

| معرف الحدث | المعنى النموذجي |
|------------|-----------------|
| 4624 | تسجيل دخول ناجح |
| 4625 | فشل تسجيل الدخول |
| 4672 | تعيين امتيازات خاصة لتسجيل دخول جديد |
| 4688 | إنشاء عملية جديدة (عند تفعيل تتبع العمليات) |
| 4720 | إنشاء حساب مستخدم |

في المختبر يمكنك توليد بعض هذه الأحداث بنفسك (تسجيلات دخول ناجحة وفاشلة) ثم العثور عليها في السجلات. هذا يبني الحدس للعمل اللاحق في الفريق الأزرق والاستجابة للحوادث.

---

## 5. المستخدمون المحليون والمجموعات والامتيازات

```powershell
Get-LocalUser
Get-LocalGroup
Get-LocalGroupMember -Group "Administrators"
whoami /priv
```

مفاهيم مهمة:

- عضوية المسؤول المحلي تمنح سلطة عالية جدًا على ذلك الجهاز.
- العديد من الامتيازات (SeDebugPrivilege وSeTakeOwnershipPrivilege وغيرها) قوية وعادة مقيدة.
- حسابات الخدمات والمهام المجدولة غالبًا ما تعمل بحقوق مرتفعة؛ فهم *أي* حساب يشغّل خدمة جزء من مراجعة سطح الهجوم.

في بيئات النطاق (Active Directory) تصبح الصورة أكبر — تتم إدارة المستخدمين والمجموعات والسياسات مركزيًا. المرحلة 0 قدّمت الفكرة؛ أمن Active Directory الأعمق موضوع متخصص لاحق.

---

## 6. أساسيات السجل للوعي الأمني

سجل Windows قاعدة بيانات هرمية لإعدادات التكوين. مواقع معينة تؤثر على الوضع الأمني:

- مواقع البدء التلقائي (الاستمرارية)
- إعدادات السياسات
- تكوين الخدمات
- معلومات تثبيت البرامج

أوامر استكشاف (القراءة فقط هي الأكثر أمانًا أثناء التعلم):

```powershell
Get-ItemProperty -Path "HKLM:\SOFTWARE\Microsoft\Windows\CurrentVersion\Run"
Get-ChildItem -Path "HKLM:\SYSTEM\CurrentControlSet\Services" | Select-Object -First 10
```

**عادة سلامة:** فضّل القراءة على الكتابة أثناء التعلم. تغيير قيم السجل يمكن أن يكسر النظام؛ احصل دائمًا على لقطة قبل التجارب.

---

## 7. الوعي بنظام الملفات والصلاحيات

يستخدم Windows قوائم التحكم في الوصول (ACLs) بدلاً من نموذج المالك/المجموعة/الآخرين البسيط في Linux.

```powershell
Get-Acl C:\Windows
Get-Acl C:\Users | Format-List
icacls C:\Windows
```

لا تحتاج إلى إتقان كل علم ACE بعد. الخلاصة العملية هي:

- من لديه صلاحيات Full Control أو Modify على المجلدات الحساسة؟
- هل هناك مشاركات أو مجلدات ذات صلاحيات مفرطة؟
- مبدأ أقل الامتيازات لا يزال ينطبق: امنح فقط ما هو مطلوب.

---

## 8. PowerShell البسيط لسكربتات التحقيق

تستخدم سكربتات PowerShell الامتداد `.ps1`. نمط آمن بسيط:

```powershell
# مقطع جرد مختبري بسيط
Write-Output "Host: $(hostname)"
Write-Output "User: $(whoami)"
Write-Output "Listening TCP ports:"
Get-NetTCPConnection -State Listen |
    Select-Object LocalAddress, LocalPort, OwningProcess |
    Format-Table -AutoSize
```

عادات جيدة:

- ابدأ بتعليقات واضحة.
- فضّل العمليات للقراءة فقط أثناء التعلم.
- اختبر السكربتات على لقطة لجهاز مختبر.
- تجنب تثبيت بيانات الاعتماد بشكل ثابت.
- استخدم `Set-ExecutionPolicy` بفهم (RemoteSigned شائع على أجهزة المختبر التي تتحكم بها).

## أخطاء شائعة

| الخطأ | المخاطر | الممارسة الأفضل |
|-------|---------|-----------------|
| تشغيل PowerShell دائمًا كمسؤول | امتياز غير ضروري؛ أصعب رؤية سلوك المستخدم العادي | ارتقِ فقط عند الحاجة |
| تجاهل OwningProcess عند النظر إلى المنافذ | لا يمكن معرفة أي برنامج يستمع | اربط دائمًا المنفذ ← العملية |
| معاملة سجلات الأحداث كضجيج | تفويت إشارة قيمة | تعلّم بضعة معرفات أحداث عالية القيمة أولاً |
| تعديل السجل دون لقطة | قد يجعل الجهاز غير قابل للإقلاع | لقطة أولاً؛ فضّل الاستكشاف للقراءة فقط |
| نسيان أن نماذج التسجيل في Windows وLinux تختلف | ارتباك عند التبديل بين البيئات | احتفظ بملاحظة مقارنة قصيرة في دفترك |

## أفضل الممارسات

- استخدم اللقطات بسخاء قبل أي تغيير تكوين أو تثبيت أداة جديدة.
- احتفظ بقائمة شخصية بـ cmdlets في PowerShell التي تستخدمها أكثر.
- عند فحص هدف مختبري، سجّل: اسم المضيف، إصدار نظام التشغيل، المنافذ المستمعة، الخدمات الجارية، وأحداث السجل المثيرة للاهتمام الأخيرة.
- مارس نفس أسئلة التحقيق على Linux وWindows حتى يصبح النموذج الذهني متسقًا.
- تذكّر أن العديد من البيئات المؤسسية تقيّد تسجيل PowerShell أو تنفيذ السكربتات — حرية المختبر امتياز وليست واقعًا عالميًا.

## أكواد عملية (Codes/)

| السكربت | الغرض |
|--------|--------|
| `Codes/PowerShell/03_windows_security/Host-Inspect.ps1` | الهوية، المنافذ المستمعة، أعلى العمليات، مجموعة Administrators |
| `Codes/PowerShell/03_windows_security/Get-ListeningPorts.ps1` | ربط منافذ TCP المستمعة باسم العملية ومسارها |
| `Codes/PowerShell/03_windows_security/Get-SecurityEvents.ps1` | أحدث أحداث سجل Security (اختياري `-LogonOnly`) |
| `Codes/PowerShell/03_windows_security/Get-StartupAndServices.ps1` | برامج البدء، الخدمات الجارية، المستخدمون المحليون |

```powershell
# من PowerShell على جهاز Windows المختبري:
Set-Location <path-to-repo>\Codes\PowerShell\03_windows_security
.\Host-Inspect.ps1
.\Get-ListeningPorts.ps1
.\Get-SecurityEvents.ps1 -MaxEvents 15 -LogonOnly
.\Get-StartupAndServices.ps1
```

إذا كان تنفيذ السكربتات مقيّدًا في جهاز المختبر:
`Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` (فقط على الأجهزة التي تتحكم بها).

**سلامة:** شغّل فقط على أجهزة Windows المختبرية التي تملكها.


على جهاز Windows افتراضي تتحكم به:

1. اسرد جميع منافذ TCP المستمعة وحدد العملية المالكة لكل منها.
2. استرجع أحدث 15 حدثًا من سجل Security ولاحظ أي إدخالات متعلقة بتسجيل الدخول.
3. اسرد أعضاء مجموعة Administrators المحلية.
4. اعرض البرامج المكوّنة للتشغيل عند البدء من مفتاح Run الشائع.
5. اكتب مقطع PowerShell قصير يطبع اسم المضيف والمستخدم الحالي ومنافذ TCP المستمعة. احفظ الناتج في دفتر ملاحظات المختبر.

**معايير النجاح:** تستطيع ربط المنافذ بالعمليات، وتحديد أحداث تسجيل الدخول الأخيرة، ولديك مقطع فحص قابل لإعادة الاستخدام.

---

## أسئلة للمراجعة

1. لماذا يُفضّل PowerShell كواجهة تحقيق على أنظمة Windows الحديثة؟
2. كيف تحدد أي عملية تملك منفذ TCP مستمع؟
3. اذكر معرفَي حدث أمني في Windows يتعلقان بنشاط تسجيل الدخول.
4. ما المخاطر العملية لتغييرات السجل دون لقطة؟
5. كيف يختلف نموذج صلاحيات Windows مفاهيميًا عن نموذج المالك/المجموعة/الآخرين في Linux؟
6. لماذا يجب تجنب تشغيل أوامر التحقيق اليومية كمسؤول؟

---

## الملخص

- Windows جزء كبير من معظم البيئات الحقيقية؛ الإلمام العملي مطلوب.
- يوفر PowerShell رؤية للعمليات والخدمات والشبكة والسجلات والتكوين.
- سجلات الأحداث، وخاصة سجل Security، مصدر تحقيق أساسي.
- ربط المنافذ المستمعة بالعمليات وفهم امتيازات الحسابات عادات أساسية.
- أقل الامتيازات واللقطات والتوثيق الحذر تظل ضرورية حتى في المختبر.
- مع وجود مهارات الفحص على Linux وWindows، أنت مستعد للانتقال إلى تحليل حركة الشبكة — الركيزة العملية الرئيسية التالية.

**المرحلة التالية:** تحليل الشبكة وبناء الحزم — رؤية وتفسير الحركة التي تتدفق بين الأنظمة.
