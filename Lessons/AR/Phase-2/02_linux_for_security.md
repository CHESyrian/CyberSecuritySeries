# المرحلة 2: Linux لممارسي الأمن

## لماذا تهم هذه المرحلة

معظم أدوات الأمن تعمل على Linux. معظم الخوادم التي ستواجهها في العمل المهني تعمل على Linux. القدرة على التحرك بثقة على نظام Linux — فحص العمليات، ومراجعة اتصالات الشبكة، وقراءة السجلات، وكتابة سكربتات مساعدة صغيرة — مهارة عملية أساسية.

المرحلة 0 قدّمت *المفاهيم* (نظام الملفات، الصلاحيات، العمليات، الخدمات، السجلات، SSH، Bash).  
هذه المرحلة تحول تلك المفاهيم إلى *عادات عمل* ستستخدمها مرارًا في المراحل اللاحقة وفي التمارين المختبرية الحقيقية.

---

## أهداف التعلم

بنهاية هذه المرحلة ستكون قادرًا على:

- التنقل في نظام الملفات وفحص الصلاحيات بثقة
- سرد وتفسير العمليات الجارية واتصالاتها الشبكية
- فحص المنافذ المستمعة والمقابس النشطة
- قراءة ملفات السجلات الشائعة وتصفيتها
- استخدام أدوات معالجة النصوص الأساسية (`grep` و`awk` و`cut` و`sort` و`uniq`) لمهام أمنية
- كتابة سكربتات Bash صغيرة وآمنة لخطوات التحقيق المتكررة
- تطبيق مبدأ أقل الامتيازات في العمل اليومي داخل المختبر

---

## نقطة التحقق الأمني

جميع الأوامر في هذه المرحلة مخصصة للتشغيل **داخل مختبرك المعزول** (جهاز الهجوم أو جهاز هدف تملكه).  
لا تشغّل أوامر تحقيق أو مسح ضد أنظمة خارج مختبرك.

---

## 1. العمل براحة على سطر الأوامر

ستقضي معظم وقتك في الطرفية. عادات مفيدة:

- استخدم إكمال التبويب (Tab).
- استخدم سهم الأعلى لاستدعاء الأوامر السابقة.
- تعلّم `man <command>` أو `<command> --help` عندما تحتاج تفاصيل.
- فضّل المسارات النسبية عندما تكون داخل مجلد؛ استخدم المسارات المطلقة عندما تكون الوضوح مهمة.

أوامر التنقل والفحص الأساسية:

| الأمر | الغرض |
|-------|-------|
| `pwd` | طباعة المجلد الحالي |
| `ls -la` | سرد الملفات مع التفاصيل والملفات المخفية |
| `cd <dir>` | تغيير المجلد |
| `file <name>` | تحديد نوع الملف |
| `stat <name>` | بيانات وصفية مفصلة (الصلاحيات، المالك، الطوابع الزمنية) |
| `which <cmd>` | تحديد موقع ملف تنفيذي |
| `find /path -name "*.log"` | البحث عن ملفات بالاسم (استخدمه بحذر) |

---

## 2. الصلاحيات عمليًا

تذكّر النموذج: المالك / المجموعة / الآخرون × قراءة / كتابة / تنفيذ.

أوامر مفيدة:

```bash
ls -l filename          # عرض الصلاحيات
stat filename           # عرض أكثر تفصيلاً
id                      # رؤية UID وGID والمجموعات الحالية
whoami                  # اسم المستخدم الحالي
```

عند إنشاء ملفات أو سكربتات في المختبر، عيّن الصلاحيات عمدًا:

```bash
chmod 644 notes.txt     # المالك قراءة/كتابة، الآخرون قراءة
chmod 755 script.sh     # المالك كامل، الآخرون قراءة+تنفيذ
chmod 600 secret.txt    # المالك فقط
```

**عادة أمنية:** تجنب منح صلاحيات قابلة للكتابة للجميع (`chmod 777`) إلا إذا كان لديك سبب محدد جدًا وتفهم المخاطر.

---

## 3. العمليات وما تفعله

العملية هي برنامج قيد التشغيل. في العمل الأمني تحتاج كثيرًا للإجابة على:

- ما الذي يعمل؟
- من يشغّله؟
- ما الملفات أو اتصالات الشبكة المفتوحة لديه؟

أوامر أساسية:

```bash
ps aux                  # لقطة لجميع العمليات
ps aux | grep <name>    # تصفية بالاسم
top                     # عرض حي (اضغط q للخروج)
htop                    # عرض حي محسّن (إن كان مثبتًا)
```

لرؤية اتصالات الشبكة والمنافذ المستمعة التابعة للعمليات:

```bash
ss -tulnp               # مقابس TCP/UDP مستمعة مع معلومات العملية
ss -tp                  # اتصالات TCP قائمة مع معلومات العملية
lsof -i                 # سرد المقابس الشبكية المفتوحة (إن كان lsof مثبتًا)
lsof -p <PID>           # الملفات والمقابس المفتوحة لعملية محددة
```

**قراءة ناتج `ss -tulnp`:**

- `State` = LISTEN يعني أن العملية تنتظر اتصالات (خدمة).
- العنوان المحلي `0.0.0.0` أو `*` يعني أنها تستمع على جميع الواجهات.
- العنوان المحلي `127.0.0.1` يعني أنها تستمع فقط على واجهة loopback (محلي فقط).

هذه الفروقات تصبح مهمة عندما تقيّم سطح الهجوم لاحقًا.

---

## 4. فحص الشبكة من المضيف

إلى جانب الأدوات المرتبطة بالعمليات، غالبًا ما تريد صورة سريعة عن وضع الشبكة للنظام:

```bash
ip addr                 # عناوين IP والواجهات
ip route                # جدول التوجيه
ss -s                   # ملخص إحصائيات المقابس
ping -c 3 <target>      # قابلية الوصول الأساسية (أهداف المختبر فقط)
```

**ملاحظة سلامة:** قصِر الفحوصات النشطة (`ping` وأي فحص منافذ وغيرها) على العناوين التي تنتمي إلى الأجهزة الافتراضية في مختبرك.

---

## 5. قراءة السجلات

السجلات من المصادر الأساسية للحقيقة لكل من المدافعين والمحققين.

مواقع شائعة في العديد من التوزيعات:

| المسار | المحتوى النموذجي |
|--------|------------------|
| `/var/log/syslog` أو `/var/log/messages` | رسائل النظام العامة |
| `/var/log/auth.log` أو `/var/log/secure` | محاولات المصادقة |
| `/var/log/kern.log` | رسائل النواة |
| `journalctl` | سجل systemd (التوزيعات الحديثة) |

أنماط قراءة مفيدة:

```bash
# آخر 50 سطرًا من سجل
tail -n 50 /var/log/auth.log

# متابعة سجل في الوقت الحقيقي
tail -f /var/log/syslog

# البحث عن مصطلح
grep -i "failed" /var/log/auth.log

# أمثلة على سجل systemd
journalctl -u ssh -n 50
journalctl --since "1 hour ago"
```

عند التحقيق في هدف مختبري، غالبًا ما تكشف السجلات عن الخدمات العاملة، وما إذا كانت هناك محاولات مصادقة، وما إذا كانت هناك أخطاء.

## 6. معالجة النصوص لمهام الأمن

العمل الأمني يتضمن كثيرًا تصفية وتلخيص النصوص (سجلات، ناتج أوامر، ملفات تكوين).

أدوات أساسية:

| الأداة | الاستخدام النموذجي |
|--------|---------------------|
| `grep` | إيجاد الأسطر المطابقة لنمط |
| `cut` | استخراج أعمدة حسب فاصل |
| `awk` | معالجة أعمدة وأنماط أكثر مرونة |
| `sort` | ترتيب الأسطر |
| `uniq` | إزالة أو عد التكرارات |
| `wc` | عد الأسطر والكلمات والبايتات |
| `head` / `tail` | أول أو آخر الأسطر |

نمط مثال (مفاهيمي):

```bash
# عد عناوين IP الفريدة التي ظهرت في حقل سجل
grep "Failed password" /var/log/auth.log | awk '{print $NF}' | sort | uniq -c | sort -nr
```

لا تحتاج إلى حفظ أوامر معقدة من سطر واحد بعد. الهدف هو الشعور بالراحة في دمج أدوات بسيطة مع الأنابيب (`|`).

---

## 7. سكربتات Bash صغيرة وآمنة

سكربت Bash هو ملف نصي يبدأ بـ shebang ويحتوي على أوامر.

قالب آمن بسيط:

```bash
#!/usr/bin/env bash
set -euo pipefail

# مثال بسيط: سرد منافذ TCP المستمعة
echo "Listening TCP sockets:"
ss -tlnp
```

عادات جيدة للسكربتات التعليمية والمختبرية:

- ابدأ بـ `#!/usr/bin/env bash`
- استخدم `set -euo pipefail` حتى يتوقف السكربت عند الأخطاء والمتغيرات غير المعرفة
- أضف تعليقات تشرح *لماذا* وليس فقط *ماذا*
- اجعل السكربت قابلاً للتنفيذ: `chmod 755 script.sh`
- فضّل المسارات الصريحة وأسماء المتغيرات الواضحة
- لا تثبّت أبدًا بيانات اعتماد حقيقية أو أسرار إنتاج

السكربتات ممتازة لأتمتة فحوصات المختبر المتكررة (مثل "أظهر لي جميع المنافذ المستمعة وآخر 20 فشل مصادقة").

---

## 8. الوعي بالامتيازات

- فضّل العمل كمستخدم عادي.
- استخدم `sudo` فقط عندما يتطلب الأمر فعلاً امتيازات مرتفعة.
- افهم أن أي عملية تبدأها ترث امتيازاتك (أو امتيازات الحساب الذي ترتقي إليه).
- في المختبر من المغري البقاء مسجلاً كـ root. قاوم هذه العادة؛ فهي تخفي مشكلات تظهر فقط تحت حسابات المستخدمين العاديين.

```bash
id                  # تأكيد هويتك
sudo -l             # رؤية ما يُسمح لك بتشغيله مع sudo (إن كان مُعدًا)
```

## أخطاء شائعة

| الخطأ | العاقبة | الممارسة الأفضل |
|-------|---------|-----------------|
| تشغيل كل شيء كـ root | يخفي مشكلات الصلاحيات؛ يزيد نطاق الضرر عند الخطأ | استخدم مستخدمًا عاديًا + sudo عند الحاجة فقط |
| البحث في نظام الملفات بالكامل بـ `find /` دون حدود | قد يكون بطيئًا وينتج ناتجًا ضخمًا | ضيّق مسار البداية وأضف مرشحات |
| تجاهل الفرق بين LISTEN على `0.0.0.0` مقابل `127.0.0.1` | سوء فهم للتعرض | لاحظ دائمًا عنوان الربط |
| نسخ أوامر معقدة ولصقها دون فهمها | آثار جانبية غير متوقعة | قسّم الأوامر واختبرها |
| ترك سكربتات أو ملفات قابلة للكتابة للجميع | يخلق مخاطر غير ضرورية حتى في المختبر | عيّن صلاحيات متعمدة |

## أفضل الممارسات

- احتفظ بورقة غش شخصية قصيرة للأوامر التي تستخدمها أكثر.
- بعد أي تغيير كبير على جهاز مختبر، أعد فحص المنافذ المستمعة والعمليات الجارية.
- عند قراءة السجلات، ابدأ واسعًا (`tail` أو `journalctl -n`) ثم ضيّق بـ `grep` أو مرشحات الوقت.
- عامل كل سكربت تكتبه على أنه شيء قد يشغّله شخص آخر لاحقًا — الوضوح مهم.
- التقط لقطة لجهاز الهجوم قبل تجربة حزم أو تغييرات تكوين جديدة.

داخل جهاز الهجوم الافتراضي (أو هدف Linux تتحكم به):

1. اسرد جميع مقابس TCP وUDP المستمعة ولاحظ العمليات التي تملكها.
2. حدد معرف عملية الصدفة الخاصة بك واسرد الملفات المفتوحة لديها.
3. اقرأ آخر 30 سطرًا متعلقًا بالمصادقة وعدّ كم عدد إدخالات "Failed" أو "Accepted".
4. اكتب سكربت Bash صغير يطبع:
   - التاريخ والوقت الحالي
   - اسم المستخدم وUID
   - ملخصًا لمنافذ TCP المستمعة
5. اجعل السكربت قابلاً للتنفيذ وشغّله. سجّل الناتج في دفتر ملاحظات المختبر.

**معايير النجاح:** تستطيع شرح ما تفعله كل عملية استماع رئيسية، ولديك سكربت يعمل، ويحتوي دفترك على الأوامر والملاحظات.

## أسئلة للمراجعة

1. ما المعلومات التي يوفرها `ss -tulnp` وتفيد بشكل خاص في العمل الأمني؟
2. لماذا يختلف ربط خدمة بـ `127.0.0.1` عن ربطها بـ `0.0.0.0`؟
3. اذكر ثلاثة مواقع سجلات أو أدوات شائعة على نظام Linux حديث.
4. ماذا يحقق `set -euo pipefail` في بداية سكربت Bash؟
5. لماذا يجب تفضيل حساب مستخدم عادي على البقاء مسجلاً كـ root أثناء عمل المختبر؟
6. أعطِ مثالاً واحدًا على دمج `grep` و`sort` و`uniq` لمهمة أمنية.

## الملخص

- الطلاقة في سطر أوامر Linux مهارة عملية أساسية للعمل الأمني.
- فحص العمليات والمقابس (`ps` و`ss` و`lsof`) يكشف ما يعمل وما هو معرّض.
- السجلات مصدر أساسي لإشارة التحقيق.
- أدوات معالجة النصوص البسيطة وسكربتات Bash الصغيرة تضاعف فعاليتك.
- انضباط الامتيازات والصلاحيات المتعمدة يظلان مهمين حتى داخل المختبر.
- بهذه العادات تكون مستعدًا لفحص أنظمة Windows من منظور أمني ثم الانتقال إلى تحليل الشبكة.

**المرحلة التالية:** Windows لممارسي الأمن — نظام التشغيل الرئيسي الآخر الذي ستواجهه في البيئات الحقيقية.
