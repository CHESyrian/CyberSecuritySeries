# 01 — الملفات وبنية النظام

## مقدمة

يقدّم Linux تقريبًا كل مورد — ملفات عادية، أدلة، أجهزة، أنابيب، مقابس، وحتى بيانات النواة — عبر واجهة نظام ملفات موحّدة. فهم هذا النموذج أساس لكل مهارة لاحقة تقريبًا: الصلاحيات، فحص العمليات، السجلات، الحزم، وأدوات الأمن.

تشرح هذه الوحدة التسلسل الهرمي لنظام الملفات، ونظام الملفات الافتراضي (VFS)، والـ inodes، ومعيار تسلسل الملفات (FHS)، وأنظمة الملفات الخاصة (`/proc`، `/sys`)، وكيف تظهر الأجهزة كملفات.

---

## أهداف التعلم

بنهاية هذه الوحدة ستكون قادرًا على:

- وصف نظام الملفات الشجري الواحد ودور الدليل الجذر `/`
- شرح ما هو الـ inode وكيف يرتبط بأسماء الملفات ومدخلات الأدلة
- التمييز بين الملفات العادية والأدلة والروابط الرمزية وملفات الأجهزة والمقابس والأنابيب المسماة
- التنقل في الأدلة العلوية الرئيسية المعرّفة في FHS وتفسيرها
- استخدام `/proc` و`/sys` لفحص معلومات النواة والعمليات
- تحديد نقاط التركيب وفهم الفرق بين نظام ملفات وشجرة أدلة

---

## المتطلبات السابقة

- القدرة على فتح طرفية وتشغيل `ls` و`cd` و`pwd` و`cat` و`less`
- إلمام مفاهيمي بفكرة «كل شيء ملف»

---

## المفاهيم الأساسية

### 1. الشجرة الهرمية الواحدة

بخلاف الأنظمة التي تخصص أحرف محركات (C:، D:)، ينظم Linux كل التخزين في شجرة واحدة تبدأ من `/` (الدليل الجذر).

- لكل ملف ودليل مسار يبدأ من `/`.
- تُركَّب الأقراص الإضافية والأقسام ومشاركات الشبكة وأنظمة الملفات الافتراضية على أدلة داخل هذه الشجرة.
- الدليل الذي يستقبل التركيب يُسمى **نقطة التركيب (mount point)**.

```
/
├── bin
├── boot
├── dev
├── etc
├── home
│   └── alice
├── lib
├── media
├── mnt
├── opt
├── proc
├── root
├── run
├── sbin
├── sys
├── tmp
├── usr
└── var
```

### 2. كل شيء ملف (تقريبًا)

في نموذج Linux:

| النوع | الوصف | مثال |
|------|--------|------|
| ملف عادي | بايتات على القرص | `/etc/passwd`، سكربت، سجل |
| دليل | ملف خاص يحتوي مدخلات دليل (اسم → inode) | `/home`، `/var/log` |
| رابط رمزي | مؤشر إلى مسار آخر | `/usr/bin/python` → `python3.11` |
| رابط صلب | اسم آخر لنفس الـ inode | (نفس الملف، اسم مختلف) |
| جهاز محرفي | جهاز تدفق بايتات | `/dev/tty`، `/dev/null` |
| جهاز كتلي | تخزين موجّه بالكتل | `/dev/sda`، `/dev/nvme0n1` |
| أنبوب مسمّى (FIFO) | تواصل بين العمليات | يُنشأ بـ `mkfifo` |
| مقبس نطاق Unix | IPC محلي | `/run/systemd/private`، مقابس كثيرة للشياطين |

يمكنك معرفة النوع بـ `ls -l` (الحرف الأول من سلسلة الصلاحيات) أو بأوامر `file` و`stat`.

### 3. الـ Inodes — الهوية الحقيقية للملف

**اسم الملف** مجرد تسمية مخزّنة داخل دليل. البيانات الوصفية وموقع البيانات الفعلي يعيشان في **inode**.

يخزّن الـ inode عادة:

- نوع الملف والصلاحيات
- UID المالك وGID المجموعة
- الحجم
- الطوابع الزمنية (وصول، تعديل، تغيير)
- عدد الروابط (كم مدخل دليل يشير إلى هذا الـ inode)
- مؤشرات إلى كتل البيانات على القرص

نتائج مهمة:

- يمكن لعدة روابط صلبة أن تشير إلى نفس الـ inode (نفس البيانات ونفس الصلاحيات).
- حذف اسم يقلل عدد الروابط؛ تُحرَّر البيانات فقط عندما يصل العدد إلى صفر **ولا** تزال أي عملية تفتح الملف.
- إعادة تسمية ملف داخل نفس نظام الملفات رخيصة — تغيّر فقط مدخل الدليل.

```bash
# فحص رقم الـ inode والبيانات الوصفية
ls -i filename
stat filename
```

### 4. نظام الملفات الافتراضي (VFS)

تقدّم النواة واجهة موحّدة (open، read، write، close، إلخ) لفضاء المستخدم بغض النظر عن نوع نظام الملفات الأساسي (ext4، xfs، btrfs، nfs، tmpfs، procfs، …). هذه الطبقة هي **نظام الملفات الافتراضي**.

برامج المستخدم تتحدث إلى VFS؛ وVFS يتحدث إلى سائق نظام الملفات المحدد.

### 5. معيار تسلسل الملفات (FHS)

يعرّف FHS الغرض المتوقع للأدلة الرئيسية حتى تعتمد البرمجيات والمسؤولون على تخطيط مشترك.

| المسار | الغرض |
|--------|--------|
| `/` | جذر التسلسل الهرمي |
| `/bin` | ثنائيات أوامر المستخدم الأساسية (قد تُدمَج مع `/usr/bin`) |
| `/boot` | ملفات محمّل الإقلاع، النواة، initramfs |
| `/dev` | ملفات الأجهزة |
| `/etc` | إعدادات النظام الخاصة بالمضيف |
| `/home` | أدلة منزل المستخدمين |
| `/lib`, `/lib64` | مكتبات مشتركة أساسية ووحدات النواة |
| `/media` | نقاط تركيب للوسائط القابلة للإزالة |
| `/mnt` | نقطة تركيب مؤقتة لاستخدام المسؤول |
| `/opt` | حزم تطبيقات اختيارية / طرف ثالث |
| `/proc` | نظام ملفات افتراضي لمعلومات العمليات والنواة |
| `/root` | دليل منزل المستخدم root |
| `/run` | بيانات متغيرة وقت التشغيل (منذ آخر إقلاع) |
| `/sbin` | ثنائيات النظام الأساسية (قد تُدمَج مع `/usr/sbin`) |
| `/srv` | بيانات للخدمات التي يقدّمها هذا النظام |
| `/sys` | نظام ملفات افتراضي للأجهزة والسائقات وكائنات النواة |
| `/tmp` | ملفات مؤقتة (غالبًا تُمسَح عند إعادة الإقلاع) |
| `/usr` | تسلسل ثانوي — بيانات قابلة للمشاركة للقراءة فقط |
| `/usr/bin` | معظم أوامر المستخدم |
| `/usr/lib` | مكتبات لـ `/usr/bin` و`/usr/sbin` |
| `/usr/local` | برمجيات مثبتة محليًا (خاصة بالموقع) |
| `/usr/share` | بيانات مستقلة عن المعمارية |
| `/var` | بيانات متغيرة — سجلات، طوابير، تخزين مؤقت، قواعد بيانات |
| `/var/log` | ملفات السجلات |
| `/var/tmp` | ملفات مؤقتة تُحفظ بين عمليات إعادة الإقلاع |

التوزيعات الحديثة غالبًا تستخدم تخطيط **merged /usr** حيث `/bin` → `/usr/bin` و`/sbin` → `/usr/sbin`.

### 6. أنظمة ملفات خاصة: `/proc` و`/sys`

هذه ليست تخزينًا حقيقيًا على القرص. تولّدها النواة عند الطلب.

#### `/proc`

- دليل واحد لكل عملية: `/proc/<PID>/`
- ملفات مفيدة داخل دليل العملية:
  - `cmdline` — سطر الأوامر
  - `status` — الحالة، UIDs، ملخص الذاكرة
  - `fd/` — واصفات الملفات المفتوحة
  - `exe` — رابط رمزي للملف التنفيذي
  - `cwd` — رابط رمزي لدليل العمل الحالي
  - `environ` — متغيرات البيئة
- معلومات على مستوى النظام:
  - `/proc/cpuinfo`
  - `/proc/meminfo`
  - `/proc/version`
  - `/proc/mounts`
  - `/proc/net/` (متعلق بالشبكة)

```bash
# مثال: فحص عملية الصدفة الحالية
echo $$
ls -l /proc/$$
cat /proc/$$/cmdline | tr '\0' ' '; echo
cat /proc/$$/status | head
```

#### `/sys` (sysfs)

يعرض كائنات النواة: الأجهزة، السائقات، الحافلات، إدارة الطاقة، الوحدات، إلخ. وهو الواجهة الحديثة لاكتشاف الأجهزة وبعض الإعدادات.

```bash
ls /sys/class/net          # واجهات الشبكة
ls /sys/block              # الأجهزة الكتلية
```

### 7. التركيبات ونقاط التركيب

يصبح نظام الملفات (قسم، مشاركة شبكة، tmpfs، إلخ) مرئيًا عندما يُركَّب على دليل.

```bash
# عرض التركيبات الحالية
mount
findmnt
cat /proc/mounts
df -h
```

مفاهيم مهمة:

- يجب أن يكون الدليل المستخدم كنقطة تركيب موجودًا مسبقًا.
- بعد التركيب، تُخفى المحتويات السابقة لذلك الدليل حتى يُفكّ التركيب.
- تركيبات الربط (bind mounts) يمكنها إرفاق جزء من الشجرة بموقع آخر.
- فضاءات الأسماء (namespaces) المستخدمة في الحاويات يمكن أن تعطي عمليات مختلفة مناظر تركيب مختلفة.

## شرح تفصيلي — ربط الأجزاء

عند تشغيل `cat /etc/passwd`:

1. تحل الصدفة المسار مكوّنًا بمكوّن بدءًا من الجذر الحالي.
2. يبحث VFS عن كل مدخل دليل، ويجد الـ inode لـ `passwd`.
3. تُفحص بتات الصلاحيات على الـ inode مقابل بيانات اعتماد العملية.
4. يقرأ سائق نظام الملفات كتل البيانات المرتبطة بذلك الـ inode.
5. تُعاد البايتات إلى عملية `cat`.

عند تشغيل `ls /proc/1`:

1. يتعرف VFS على أن `/proc` نظام ملفات خاص.
2. يولّد سائق procfs مدخلات الدليل ومحتويات الملفات من هياكل بيانات النواة لـ PID 1 (عادة systemd أو init).
3. لا يحدث إدخال/إخراج قرص للمحتوى نفسه؛ يُولَّد حيًا.

هذه الواجهة الموحّدة هي سبب عمل نفس الأدوات (`cat`، `ls`، `grep`، `less`) على ملفات الإعداد والسجلات ومعلومات الأجهزة وحالة العمليات.

## أمثلة عملية

### فحص هوية ملف

```bash
touch /tmp/demo.txt
ls -li /tmp/demo.txt
stat /tmp/demo.txt

# إنشاء رابط صلب
ln /tmp/demo.txt /tmp/demo-hard.txt
ls -li /tmp/demo.txt /tmp/demo-hard.txt
# نفس رقم الـ inode، عدد الروابط = 2

# إنشاء رابط رمزي
ln -s /tmp/demo.txt /tmp/demo-sym.txt
ls -li /tmp/demo-sym.txt
# inode مختلف؛ للرابط الرمزي inode صغير خاص به يخزّن مسار الهدف
```

### استكشاف التسلسل الهرمي

```bash
ls -l /
ls /bin /usr/bin | head
ls /etc | head
ls /var/log
ls /dev | head
ls /proc | head
ls /sys/class
```

### معلومات العملية عبر /proc

```bash
# عمليتك الحالية
PID=$$
echo "PID: $PID"
cat /proc/$PID/status | grep -E 'Name|State|Uid|Gid|VmSize'
ls -l /proc/$PID/fd
readlink /proc/$PID/exe
```

### معلومات التركيب

```bash
findmnt -D
df -hT
```

## أخطاء شائعة

| الخطأ | لماذا يهم | نهج أفضل |
|-------|-----------|----------|
| معاملة الرابط الرمزي كالملف الحقيقي عند التحرير | قد تعدّل الهدف الخطأ أو تنشئ رابطًا مكسورًا | استخدم `readlink -f` أو `realpath` للحل؛ `ls -l` لرؤية الهدف |
| افتراض أن `/tmp` خاص | يمكن لمستخدمين آخرين غالبًا قراءة الملفات ذات القراءة للجميع هناك | استخدم `mktemp` واضبط صلاحيات مقيدة، أو استخدم دليلًا خاصًا |
| حذف ملف لا تزال عملية تفتحه | مساحة القرص لا تُحرَّر حتى تغلق العملية الملف | تحقق بـ `lsof` أو `fuser` قبل افتراض استعادة المساحة |
| كتابة بيانات كبيرة في `/` أو ملء `/var` | يمكن أن يجعل النظام غير قابل للإقلاع أو يكسر الخدمات | راقب بـ `df -h`؛ الأقسام المنفصلة أو المجلدات المنطقية تساعد |
| الخلط بين الروابط الصلبة والرمزية | الروابط الصلبة لا تعبر أنظمة الملفات؛ الرمزية يمكن أن تتدلى | اعرف أيهما تحتاج؛ فضّل الرمزية لمعظم المراجع عبر الأدلة |

## أفضل الممارسات

- فضّل المسارات المطلقة في السكربتات والوثائق عندما تكون الوضوح مهمة.
- استخدم `stat` و`ls -li` عندما تحتاج التفكير في الهوية مقابل الاسم.
- عامل `/proc` و`/sys` كواجهات للقراءة في الغالب؛ تغيير القيم تحت `/sys` يمكن أن يغيّر سلوك العتاد أو النواة.
- راقب استخدام القرص لـ `/var/log` و`/tmp`.
- عند استكشاف نظام غير مألوف، ابدأ بـ `findmnt` و`df -h` و`ls /` و`ls /etc` للتوجيه.

---

## تمرين عملي

نفّذ هذه الخطوات على جهاز مختبر تتحكم به.

1. أنشئ ملفًا عاديًا ورابطًا صلبًا ورابطًا رمزيًا. سجّل أرقام الـ inode بـ `ls -li`.
2. اعرض محتويات `/proc/self` وحدّد خمسة ملفات مفيدة على الأقل. اشرح ماذا يخبرك كل منها.
3. شغّل `findmnt` وحدّد نظام الملفات الذي يحتوي دليل منزلك والذي يحتوي `/`.
4. استخدم `df -h` ولاحظ أي نقاط التركيب أقرب للامتلاء.
5. حدد ملف الجهاز الذي يقابل نظام ملفات الجذر (تلميح: ابدأ من `findmnt` أو `/proc/mounts`).

---

## أسئلة المراجعة

1. ما الفرق بين الرابط الصلب والرابط الرمزي؟
2. لماذا يمكن لاسمين مختلفين أن يشيران إلى نفس البيانات والبيانات الوصفية تمامًا؟
3. ماذا يشير الحرف الأول في قائمة `ls -l`؟
4. اذكر ثلاث قطع معلومات يمكنك الحصول عليها عن عملية بالنظر تحت `/proc/<PID>/`.
5. لماذا يُسمى `/proc` نظام ملفات افتراضيًا؟
6. ما هي نقطة التركيب؟
7. وفقًا لـ FHS، أين يجب أن تعيش ملفات الإعداد الخاصة بالمضيف؟ وأين بيانات السجلات المتغيرة؟

---

## ملخص

- يقدّم Linux فضاء أسماء هرميًا واحدًا يبدأ من `/`.
- أسماء الملفات مدخلات دليل؛ الكائن الحقيقي هو الـ inode.
- الملفات العادية والأدلة والأجهزة والمقابس والأنابيب تُوصَل جميعًا عبر نفس واجهة VFS.
- يعرّف FHS مواقع تقليدية للثنائيات والإعدادات والسجلات وبيانات التشغيل.
- `/proc` و`/sys` يعرضان حالة النواة والعمليات الحية كملفات.
- فهم التركيبات والـ inodes ونموذج «كل شيء ملف» مطلوب قبل أن تصبح الامتيازات والعمليات وأدوات الأمن منطقية بالكامل.
