# 02 — المستخدمون والمجموعات

## مقدمة

كل عملية على نظام Linux تعمل بمجموعة من بيانات الاعتماد: معرّف مستخدم (UID)، ومعرّف مجموعة (GID)، وقائمة مجموعات إضافية. تحدد هذه الاعتمادات ما يُسمح للعملية بفعله. فهم كيفية تعريف الحسابات، وأين تعيش البيانات، وكيف تستخدم النواة UIDs وGIDs ضروري لإدارة الأنظمة والعمل الأمني.

تغطي هذه الوحدة قواعد بيانات المستخدمين والمجموعات، والفرق بين الأسماء والمعرّفات الرقمية، والدور الخاص لـ root، وأدلة المنزل، والأوامر المستخدمة لفحص الهوية وإدارتها.

---

## أهداف التعلم

بنهاية هذه الوحدة ستكون قادرًا على:

- شرح الفرق بين اسم المستخدم وUID، وبين اسم المجموعة وGID
- قراءة وتفسير `/etc/passwd` و`/etc/group` و`/etc/shadow`
- وصف ما يحدث عند تسجيل الدخول وكيف تُضبط بيانات اعتماد العملية
- سرد مجموعات مستخدم وتحديد الهوية الفعلية للعملية الحالية
- فهم الوضع الخاص لـ UID 0 (root) وحسابات الخدمات/النظام
- استخدام أوامر فحص الحسابات الشائعة بأمان في المختبر

## المفاهيم الأساسية

### 1. الهوية رقمية

تهتم النواة بـ **الأرقام** وليس الأسماء:

- **UID** — معرّف المستخدم (عدد صحيح غير سالب)
- **GID** — معرّف المجموعة

الأسماء (`alice`، `sudo`، `root`) موجودة للبشر. تُحل عبر قواعد بيانات (عادة ملفات محلية، وأحيانًا خدمات شبكية مثل LDAP/SSSD).

اصطلاحات شائعة:

| نطاق UID / GID | الاستخدام النموذجي |
|----------------|-------------------|
| 0 | root |
| 1–99 أو 1–999 | حسابات نظام / خدمات (يعتمد على التوزيع) |
| 1000+ | مستخدمون بشريون عاديون (افتراضي شائع في كثير من التوزيعات) |

النطاقات الدقيقة تُضبط في `/etc/login.defs` وقد تختلف.

### 2. المجموعة الأساسية والمجموعات الإضافية

- لكل مستخدم **مجموعة أساسية** واحدة بالضبط (الـ GID المخزّن في قاعدة بيانات المستخدم).
- قد ينتمي المستخدم إلى **مجموعات إضافية** أخرى.
- عندما تنشئ عملية ملفًا جديدًا، تكون مجموعة الملف عادةً الـ GID الأساسي للعملية (ما لم يكن للدليل الأب بت setgid).

### 3. ملفات قواعد البيانات الكلاسيكية الثلاثة

#### `/etc/passwd` — معلومات حساب المستخدم (قابل للقراءة للجميع)

التنسيق (حقول مفصولة بنقطتين):

```
username:password_placeholder:UID:GID:GECOS:home_directory:shell
```

| الحقل | المعنى |
|-------|--------|
| username | اسم تسجيل الدخول |
| password_placeholder | تقريبًا دائمًا `x` (بيانات كلمة المرور الحقيقية في `/etc/shadow`) |
| UID | معرّف المستخدم الرقمي |
| GID | معرّف المجموعة الأساسية الرقمي |
| GECOS | تعليق اختياري (الاسم الكامل، جهة الاتصال، إلخ) |
| home_directory | المسار المطلق لمنزل المستخدم |
| shell | المسار المطلق لصدفة تسجيل الدخول (أو `/sbin/nologin`، `/bin/false` للحسابات غير التفاعلية) |

مثال سطر:

```
alice:x:1001:1001:Alice Example,,,:/home/alice:/bin/bash
```

#### `/etc/shadow` — بيانات المصادقة الحساسة (قابل للقراءة لـ root فقط)

```
username:hashed_password:lastchange:min:max:warn:inactive:expire:reserved
```

حقل كلمة المرور المشفّرة قد يحتوي:

- تجزئة حقيقية (مثل `$6$...` لـ SHA-512)
- `!` أو `*` — الحساب مقفل / لا تسجيل دخول بكلمة مرور
- فارغ — (نادر وغير آمن)

لا تنسخ `/etc/shadow` خارج مختبر متحكم به أبدًا. يحتوي مواد يمكن استخدامها لهجمات كلمات المرور دون اتصال.

#### `/etc/group` — تعريفات المجموعات

```
groupname:password_placeholder:GID:member1,member2,...
```

قائمة الأعضاء تحتوي أسماء المستخدمين الذين لديهم هذه المجموعة كـ **مجموعة إضافية**. علاقة المجموعة الأساسية مخزّنة في `/etc/passwd`، وليست بالضرورة مكررة هنا.

### 4. Root — UID 0

الحساب ذو UID 0 يُسمى تقليديًا `root`. تمنحه النواة امتيازًا غير مقيد تقريبًا. كثير من ضوابط الأمن (صلاحيات الملفات، فحوصات الـ capabilities، إلخ) تعامل UID 0 كحالة خاصة.

أفضل ممارسة: اعمل يوميًا كمستخدم عادي؛ ارفع الامتياز فقط عند الضرورة (عبر `sudo` أو صدفة root متحكم بها).

### 5. حسابات النظام والخدمات

تعمل الشياطين والخدمات عادة تحت حسابات مخصصة منخفضة الامتياز (مثل `www-data`، `nginx`، `postgres`، `nobody`). هذه الحسابات:

- غالبًا لها صدفة غير تسجيل دخول (`/usr/sbin/nologin` أو `/bin/false`)
- لها أدلة منزل قد لا تكون منازل تفاعلية عادية
- موجودة حتى لا يمنح اختراق خدمة تلقائيًا وصول root كامل

### 6. أدلة المنزل والهيكل العظمي

- يحصل المستخدمون العاديون عادة على دليل تحت `/home`.
- منزل مستخدم root هو `/root` (ليس تحت `/home`).
- عند إنشاء مستخدم بالأدوات المعتادة، تُنسَخ ملفات من `/etc/skel` إلى الدليل الجديد (مثل `.bashrc`، `.profile` الافتراضية).

## شرح تفصيلي

### كيف تُنشأ بيانات الاعتماد

1. يصادق المستخدم (كلمة مرور، مفتاح، إلخ).
2. تبحث عملية تسجيل الدخول (أو مدير العرض، أو `sshd`) عن الحساب.
3. تُنشأ عملية جديدة بـ:
   - Real UID / effective UID = UID المستخدم
   - Real GID / effective GID = GID الأساسي للمستخدم
   - المجموعات الإضافية = المجموعات المدرجة لذلك المستخدم
4. تنتقل العملية إلى دليل منزل المستخدم وتبدأ صدفة تسجيل الدخول (أو الأمر المطلوب).

لاحقًا، يمكن للعملية تغيير بيانات اعتمادها فقط تحت قواعد صارمة (ثنائيات setuid، capabilities، أو امتياز root).

### فحص الهوية

```bash
# من أنا؟
whoami
id
id alice

# عرض رقمي
id -u
id -g
id -G

# مجموعات مستخدم
groups
groups alice

# جلسات تسجيل الدخول الحالية
who
w
```

أمر `id` هو الأداة الأهم: يعرض UID وGID وجميع المجموعات بالاسم والشكل الرقمي.

### أوامر إدارة الحسابات (استخدام المختبر)

تعدّل هذه الأوامر حالة النظام. استخدمها فقط على أجهزة تملكها أو مصرح لك بإدارتها.

```bash
# إنشاء مستخدم (أسلوب Debian/Ubuntu)
sudo adduser alice

# إنشاء مستخدم بتحكم أكثر (مستوى أدنى)
sudo useradd -m -s /bin/bash bob

# إنشاء مجموعة
sudo groupadd developers

# إضافة مستخدم إلى مجموعة إضافية
sudo usermod -aG developers alice

# قفل / إلغاء القفل
sudo passwd -l alice
sudo passwd -u alice

# تغيير الصدفة
sudo chsh -s /bin/bash alice
```

فضّل دائمًا أداة التوزيع عالية المستوى الموصى بها (`adduser` / `useradd`، `usermod`، إلخ) واقرأ صفحة الدليل للخيارات الدقيقة على نظامك.

## أمثلة عملية

### قراءة قواعد البيانات (كمستخدم عادي)

```bash
# معلومات عامة
getent passwd alice
getent passwd 1001
getent group sudo
getent group 27

# عد المستخدمين المحليين
getent passwd | wc -l
```

يُفضَّل `getent` على `cat` المباشر للملفات لأنه يعمل أيضًا عندما تأتي الحسابات من مصادر شبكية (LDAP، إلخ).

### فحص بيانات اعتماد العملية الحالية

```bash
id
cat /proc/$$/status | grep -E 'Uid|Gid|Groups'
```

### النظر إلى حساب خدمة

```bash
getent passwd www-data
getent passwd nobody
ls -ld /var/www 2>/dev/null || true
```

## أخطاء شائعة

| الخطأ | لماذا مشكلة | ممارسة أفضل |
|-------|-------------|-------------|
| تحرير `/etc/passwd` أو `/etc/shadow` يدويًا دون قفل | خطر الفساد أو التغيير المتزامن | استخدم `vipw`، `vipw -s`، أو أدوات الحساب المناسبة |
| افتراض أن المجموعة الأساسية مدرجة في حقل أعضاء `/etc/group` | المجموعة الأساسية معرّفة في `/etc/passwd` | تحقق دائمًا من المصدرين أو استخدم `id` |
| منح حساب خدمة صدفة تسجيل دخول | يزيد سطح الهجوم إذا اختُرق الحساب | استخدم `/usr/sbin/nologin` أو ما يعادله |
| تشغيل العمل اليومي كـ root | أي خطأ أو أمر خبيث له قوة كاملة | استخدم حسابًا عاديًا + `sudo` |
| نسيان أن UIDs يجب أن تكون فريدة | اسمان بنفس UID هما نفس الهوية للنواة | دع أدوات الحساب تخصص UIDs |

---

## أفضل الممارسات

- استخدم `id` و`getent` للفحص؛ أكثر أمانًا وقابلية للنقل من تحليل الملفات يدويًا.
- اجعل استخدام root وsudo مقصودًا ومسجّلاً.
- فضّل حسابات خدمة مخصصة على تشغيل الشياطين كـ root.
- عامل `/etc/shadow` كمادة شديدة الحساسية.
- وثّق أي حساب أو مجموعة محلية تنشئها في المختبر حتى تتمكن من التنظيف لاحقًا.
- على الأنظمة المنضمة إلى نطاق، تذكّر أن الملفات المحلية ليست المصدر الوحيد للهوية.

---

## تمرين عملي

على نظام مختبر:

1. شغّل `id` و`whoami`. سجّل UID وGID الأساسي والمجموعات الإضافية.
2. استخدم `getent passwd $USER` واربط كل حقل بمعناه.
3. اسرد جميع المجموعات التي تنتمي إليها بـ `id -Gn` و`groups`.
4. افحص حساب نظام (مثل `nobody` أو `www-data` إن وُجد). ما صدفته؟ منزله؟
5. (اختياري، إن كان لديك sudo) أنشئ مستخدمًا مؤقتًا ومجموعة مؤقتة، أضف المستخدم للمجموعة، تحقق بـ `id`، ثم احذفهما بشكل نظيف.

---

## أسئلة المراجعة

1. ما الفرق بين اسم المستخدم وUID من وجهة نظر النواة؟
2. أي ملف يخزّن كلمة المرور المشفّرة في إعداد حساب محلي نموذجي؟
3. ماذا يمثل الحقل السابع في `/etc/passwd`؟
4. لماذا تستخدم كثير من حسابات الخدمة `/usr/sbin/nologin` كصدفة؟
5. كيف ترى المجموعة الكاملة للعملية الحالية؟
6. ما الخاص في UID 0؟
7. لماذا غالبًا ما يكون `getent passwd` أفضل من `cat /etc/passwd`؟

---

## ملخص

- تفوّض النواة الإجراءات بناءً على UIDs وGIDs رقمية.
- `/etc/passwd` و`/etc/shadow` و`/etc/group` (أو مكافئاتها الشبكية) تعرّف الحسابات والمجموعات.
- root (UID 0) كلي القدرة؛ يجب أداء العمل العادي تحت حسابات غير مميزة.
- حسابات الخدمة تعزل الشياطين عن بعضها وعن المستخدمين التفاعليين.
- أوامر مثل `id` و`getent` و`groups` و`whoami` هي الأدوات الأساسية لفحص الهوية.
