# المسار 1 · أمان تطبيقات الويب  
## من الوعي بالويب إلى تقييم التطبيقات في المختبر

**لمن هذا المسار؟**  
للمتعلمين الذين أنهوا المرحلة 2 ويريدون عمقاً في كيفية بناء تطبيقات الويب وكسرها (في مختبرات منضبطة) ومراقبتها وتقويتها. مناسب إن كنت تميل إلى AppSec أو اختبار الويب أو الدفاع عن الأنظمة المواجهة للويب.

**ماذا ستكون قادراً على فعله في النهاية**
- شرح دورة الطلب/الاستجابة والجلسات وملفات تعريف الارتباط وأنماط المصادقة الشائعة بلغة أمنية
- رسم خريطة لتطبيق ويب مختبري بأدوات المتصفح ووكيل اعتراض
- التعرف على فئات المشكلات الرئيسية وإظهارها بأمان على تطبيقات *ضعيفة عمداً* (الحقن، XSS، التحكم في الوصول، سوء التكوين، إلخ)
- اختبار ومراقبة سلوكيات API بسيطة في المختبر
- اقتراح تقوية عملية (ترويسات، TLS، أعلام الجلسة، أقل الامتيازات)
- إنتاج تقرير تقييم منظم يصلح كقطعة محفظة

## أهداف المختبر (مصرح بها فقط)

استخدم تطبيقات **مصممة للتدريب** مستضافة في مختبرك المعزول:

| الهدف | الاستخدام النموذجي في هذا المسار |
|------|----------------------------------|
| **OWASP Juice Shop** | تطبيق حديث، سطح نتائج غني، جيد للخريطة والتقرير |
| **DVWA** | ثغرات كلاسيكية متعمدة، جيدة لتمارين الحقن/XSS |
| **WebGoat** / مشابه | دروس موجّهة متوافقة مع فئات المشكلات |
| تطبيق ضعيف مخصص كتبته أو استوردته | ممارسة متقدمة اختيارية |

**لا** تستخدم مواقع إنتاج أو تطبيقات صاحب العمل أو أنظمة طرف ثالث دون قواعد اشتباك مكتوبة.

## نقاط تحقق السلامة (المسار 1)

قبل كل مرحلة نشطة:

1. أكد أن عنوان IP/URL الهدف جهاز مختبر أو حاوية تتحكم بها.  
2. أكد أن الوكيل (إن وُجد) موجّه فقط لحركة المختبر.  
3. فضّل إثباتات غير مدمرة (ملاحظة، حمولات آمنة على تطبيقات التدريب).  
4. لا حشو بيانات اعتماد ضد قواعد مستخدمين حقيقية؛ حسابات المختبر فقط.  
5. لقطة للهدف قبل التجارب العدوانية.

مراحل الحقن وXSS تعلّم **التعرف والإظهار المنضبط على مختبرات مقصودة**، وليس التسليح للإنترنت المفتوح.

## ملخصات المراحل

### 1.1 — HTTP والجلسات والمصادقة
إعادة بناء معرفة المرحلة 2 بعمق: الطرق، رموز الحالة، الترويسات الحساسة، سمات ملفات تعريف الارتباط، دورة حياة الجلسة، أنماط المصادقة.  
**تمرين:** التقط حركة تسجيل دخول وتصفح عادية لتطبيق المختبر؛ وثّق ملفات تعريف الارتباط وإعادة التوجيه.

### 1.2 — رسم الخرائط وسير عمل الوكيل
رسم منهجي: اكتشاف المحتوى، خريطة الموقع، المعلمات، السطح المصادق وغير المصادق. إعداد وكيل اعتراض للمختبر فقط.  
**تمرين:** ارسم خريطة Juice Shop أو DVWA؛ صدّر خريطة موقع بسيطة وقائمة معلمات.

### 1.3 — الحقن في المختبر
كيف تتحول المدخلات غير الموثوقة إلى استعلامات أو أوامر عند المعالجة السيئة. حقن SQL وحقن الأوامر *على صفحات مختبر مقصودة فقط*.  
**تمرين:** أكمل تحديات الحقن المخصصة في DVWA/Juice Shop؛ سجّل الطلب وفئة الحمولة والنتيجة.

### 1.4 — XSS وجانب العميل
XSS المنعكس والمخزّن والقائم على DOM كمفاهيم؛ عرض آمن في تطبيقات المختبر؛ أهمية ترميز المخرجات وCSP.  
**تمرين:** شغّل مختبرات XSS المقصودة؛ اذكر المصدر/المصب في مذكرتك؛ اقترح إصلاحاً بلغة بسيطة.

### 1.5 — التحكم في الوصول وIDOR
مشكلات الامتيازات الرأسية/الأفقية؛ المراجع المباشرة غير الآمنة للكائنات.  
**تمرين:** غيّر معرفات كائنات أو أدوار داخل تطبيق التدريب فقط؛ وثّق فجوات التفويض.

### 1.6 — واجهات API والتطبيقات الحديثة
أفعال REST وJSON ورموز الحالة ومفاهيم المفاتيح/JWT ومشكلات مختبرية شائعة.  
**تمرين:** راقب استدعاءات API من تطبيق المختبر؛ سكربت Python صغير بـ `requests` ضد API *المختبر* فقط.

### 1.7 — التقوية والدفاع
ترويسات الأمان، تذكير بتكوين TLS، مهلة الجلسة، أقل امتيازات لحساب قاعدة البيانات، تسجيل إخفاقات المصادقة. WAF كطبقة وليس حلاً سحرياً.  
**تمرين:** قائمة تحقق ضد تطبيق مختبرك؛ فعّل أو أوصِ بتحسينَي تقوية ملموسين.

### 1.8 — المشروع الختامي للمسار
تقييم من طرف إلى طرف لـ**تطبيق مختبر واحد**: النطاق، المنهجية، النتائج (مع أدلة)، منطق تقييم المخاطر، المعالجة، ملاحظات إعادة الاختبار.  
**المخرج:** تقرير بأسلوب المحفظة (البنية تُقدَّم في ملف المرحلة).
