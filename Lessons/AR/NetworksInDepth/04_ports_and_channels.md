# 04 — المنافذ والقنوات

## مقدمة

تتيح المنافذ لتطبيقات شبكة متعددة على نفس المضيف مشاركة عنوان IP واحد. مع عنوان IP تشكّل **نقطة نهاية مقبس**. فهم نطاقات المنافذ والخدمات المعروفة والمنافذ العابرة ومفهوم القنوات أساسي لسياسة جدار النار وتحديد الخدمات وتحليل الحركة.

---

## أهداف التعلم

- شرح دور أرقام المنافذ في TCP وUDP
- التمييز بين نطاقات المنافذ المعروفة والمسجلة والعابرة
- تعريف المقبس والاتصال (الخماسية)
- التعرف على منافذ الخدمات الشائعة وآثارها الأمنية
- وصف التعدد وكيف تشارك محادثات كثيرة واجهة واحدة
- تطبيق معرفة المنافذ على قواعد جدار النار وتدقيق الخدمات المستمعة

---

## المفاهيم الأساسية

### 1. ما هو المنفذ

المنفذ رقم 16 بت (0–65535) يعرّف نقطة نهاية محددة لـ TCP أو UDP على مضيف.

- **منفذ المصدر** — عادة يختاره العميل (غالبًا عابر)
- **منفذ الوجهة** — عادة المنفذ المعروف أو المسجل للخدمة

المزيج:

```
(عنوان IP، البروتوكول، المنفذ)
```

يعرّف مقبسًا. يُعرَّف اتصال TCP بشكل فريد بـ **الخماسية**:

```
(IP المصدر، منفذ المصدر، IP الوجهة، منفذ الوجهة، البروتوكول)
```

### 2. نطاقات أرقام المنافذ

| النطاق | الاسم | الاستخدام النموذجي |
|--------|-------|-------------------|
| 0–1023 | معروفة / نظام | خدمات مميزة (HTTP 80، HTTPS 443، SSH 22، DNS 53، …). الربط غالبًا يتطلب امتيازات مرتفعة. |
| 1024–49151 | مسجلة | مسجلة لدى IANA لتطبيقات محددة |
| 49152–65535 | ديناميكية / عابرة | منافذ عميل مؤقتة تخصصها نظام التشغيل |

يمكن ضبط النطاق العابر الدقيق على بعض الأنظمة (`/proc/sys/net/ipv4/ip_local_port_range` على Linux).

### 3. منافذ شائعة (مجموعة فرعية ذات صلة بالأمن)

| المنفذ | البروتوكول | الخدمة | ملاحظات |
|--------|------------|--------|---------|
| 20/21 | TCP | FTP بيانات/تحكم | نص واضح؛ فضّل SFTP |
| 22 | TCP | SSH | وصول عن بُعد مشفر |
| 23 | TCP | Telnet | نص واضح؛ عطّل |
| 25 | TCP | SMTP | نقل بريد |
| 53 | TCP/UDP | DNS | بنية تحتية حرجة |
| 67/68 | UDP | DHCP | إعداد محلي |
| 80 | TCP | HTTP | ويب نص واضح |
| 110 | TCP | POP3 | استرجاع بريد |
| 123 | UDP | NTP | وقت |
| 143 | TCP | IMAP | وصول بريد |
| 161/162 | UDP | SNMP | مراقبة |
| 389 | TCP | LDAP | دليل |
| 443 | TCP | HTTPS | HTTP محمي بـ TLS |
| 445 | TCP | SMB | مشاركة ملفات Windows |
| 636 | TCP | LDAPS | LDAP فوق TLS |
| 993 | TCP | IMAPS | IMAP فوق TLS |
| 995 | TCP | POP3S | POP3 فوق TLS |
| 3389 | TCP | RDP | سطح مكتب بعيد Windows |
| 3306 | TCP | MySQL | قاعدة بيانات |
| 5432 | TCP | PostgreSQL | قاعدة بيانات |
| 5900+ | TCP | VNC | عرض بعيد |
| 8080 / 8443 | TCP | HTTP/HTTPS بديل | غالبًا خوادم تطبيقات أو وكلاء |

تحقق دائمًا مما يستمع فعليًا؛ أرقام المنافذ اصطلاحات وليست ضمانات.

### 4. القنوات والتعدد

- يمكن لواجهة شبكة واحدة دعم آلاف اتصالات TCP ومحادثات UDP المتزامنة لأن كلًا منها يُميَّز بالخماسية (أو رباعية UDP زائد سياق التطبيق).
- **التعدد** — تدفقات تطبيق كثيرة تشارك نفس مسار الطبقة الأدنى.
- **إلغاء التعدد** — يسلّم نظام التشغيل المقاطع/مخططات البيانات الواردة إلى المقبس الصحيح بناءً على معلومات المنفذ (والعنوان).

«القناة» تُستخدم أحيانًا بشكل غير رسمي لـ:

- اتصال TCP
- جلسة TLS فوق TCP
- جلسة SSH أو نفق SSH
- مسار منطقي عبر جدار نار أو VPN

### 5. الاستماع مقابل المؤسس

```bash
# مقابس مستمعة
ss -tuln
ss -tulpn          # مع معلومات العملية (قد يحتاج root)

# اتصالات مؤسسة
ss -tan
ss -tp
```

حالات تراها لـ TCP تشمل LISTEN، SYN-SENT، SYN-RECV، ESTABLISHED، FIN-WAIT، TIME-WAIT، CLOSE-WAIT، إلخ.

### 6. جدران النار وسياسة المنافذ

- **رفض افتراضي** للوارد: فقط منافذ الوجهة المسموحة صراحة مفتوحة.
- تصفية الصادر تزداد أهمية (حد منافذ ووجهات الصادر).
- جدران النار ذات الحالة تتبع الخماسية حتى يُسمح بحركة العودة للاتصالات الصادرة المسموحة تلقائيًا.
- طرق متقدمة مثل طرق الطرق ومنح صلاحية الحزمة الواحدة وبوابات طبقة التطبيق؛ جدران النار الأساسية للمضيف والشبكة تبقى الأساس.

## أمثلة عملية

```bash
# ما يستمع على هذا المضيف؟
ss -tulpn

# أي عملية تملك منفذًا معينًا؟ (Linux)
sudo ss -tulpn | grep ':22'
sudo lsof -i :22

# نطاق المنافذ العابرة
cat /proc/sys/net/ipv4/ip_local_port_range

# فحص اتصال بسيط
nc -zv example.com 443
curl -I https://example.com
```

## أخطاء شائعة

| الخطأ | الخطر |
|-------|-------|
| افتراض أن منفذًا مغلقًا يعني غياب الخدمة | قد تستمع الخدمة على واجهة أو منفذ آخر؛ أو تكون مصفاة |
| فتح نطاقات منافذ واسعة «مؤقتًا» | قواعد منسية تصبح سطح هجوم دائم |
| الاعتماد فقط على أرقام المنافذ للتعريف | يمكن للمهاجمين تشغيل خدمات على منافذ غير متوقعة؛ اربط دائمًا مع العملية وبيانات الشهادة |
| تجاهل منافذ الصادر | البرمجيات الخبيثة والتسريب غالبًا تستخدمان منافذ صادر شائعة (80/443) أو منافذ عالية |

## أفضل الممارسات

- جرّد المنافذ المستمعة بانتظام على المضيفين الحرجين.
- طبّق مرشحات قائمة على المضيف والشبكة بوضعية رفض افتراضي.
- فضّل المنافذ غير الافتراضية فقط عند دمجها مع مصادقة قوية ومراقبة — الأمن بالغموض وحده غير كافٍ.
- وثّق الخدمات المطلوبة ومنافذها لكل شريحة شبكة.
- في المختبرات، تدرب على تعيين المنافذ → العمليات → ملفات الإعداد.

---

## تمرين عملي

1. اسرد كل مقابس TCP وUDP المستمعة على جهاز مختبر وحدّد العملية المالكة حيث أمكن.
2. حدد نطاق المنافذ العابرة على نظامك.
3. من عميل، افتح اتصال HTTPS ولاحظ منفذ المصدر (العابر) ومنفذ الوجهة 443 بـ `ss` أو التقاط.
4. اكتب مجموعة قواعد جدار نار دنيا (مفاهيميًا أو بـ `nftables`/`iptables` في مختبر) تسمح بـ SSH وHTTPS وارد وDNS صادر.

---

## أسئلة المراجعة

1. ما النطاق العددي للمنافذ المعروفة؟
2. أي خمس قطع معلومات تعرّف اتصال TCP بشكل فريد؟
3. لماذا تستخدم اتصالات العميل عادة منافذ مصدر عالية الرقم؟
4. ماذا يمثل مقبس في حالة LISTEN؟
5. لماذا تصفية منافذ الوجهة فقط غير مكتملة للتهديدات الحديثة؟

---

## ملخص

تتيح المنافذ تعدد خدمات ومحادثات كثيرة على عناوين IP مشتركة. معرفة النطاقات القياسية ومنافذ الخدمات الشائعة ونموذج الخماسية أساسي لاكتشاف الخدمات وتصميم جدار النار وتحليل الحركة. تحقق دائمًا من المستمعين والعمليات الفعليين بدل الثقة بأرقام المنافذ وحدها.

---

## المصادر

- سجل IANA لأسماء الخدمات وأرقام منافذ بروتوكول النقل
- صفحات دليل Linux: `ss(8)`، `lsof(8)`، `ip(8)`
- وثائق جدار النار (nftables، iptables، مجموعات أمن السحابة)
