# 03 — البروتوكولات

## مقدمة

البروتوكول مجموعة قواعد متفق عليها تعرّف تنسيق ومعنى الرسائل المتبادلة بين الكيانات. تستعرض هذه الوحدة البروتوكولات الرئيسية التي ستواجهها في بيئات المؤسسات والإنترنت، منظمة تقريبًا حسب الطبقة، مع التركيز على الغرض والحقول الرئيسية والأهمية الأمنية.

«كل البروتوكولات» غير محدود؛ التركيز هنا على البروتوكولات التي تهيمن على الحركة الحقيقية وعمل الأمن.

---

## أهداف التعلم

- شرح غرض البروتوكولات الرئيسية في كل طبقة
- تحديد حقول الترويسة الرئيسية لـ Ethernet وIP وTCP وUDP وبروتوكولات التطبيق الشائعة
- التمييز بين السلوك الموجّه بالاتصال والسلوك بلا اتصال
- التعرف على البروتوكولات التي توفر السرية أو السلامة أو المصادقة
- ربط سلوك البروتوكول بضوابط الأمن والهجمات الشائعة (منظور مفاهيمي دفاعي)

---

## المفاهيم الأساسية حسب الطبقة

### الطبقة 2 — Ethernet وARP

**Ethernet (IEEE 802.3)**

- بنية الإطار (مبسّطة): MAC الوجهة | MAC المصدر | EtherType | الحمولة | FCS
- يشير EtherType إلى بروتوكول الطبقة العليا (مثل 0x0800 = IPv4، 0x86DD = IPv6، 0x0806 = ARP)
- MTU عادة 1500 بايت للإطارات القياسية

**ARP (بروتوكول حل العناوين)**

- يحل عنوان IPv4 → عنوان MAC على الرابط المحلي
- الطلب بث؛ الرد عادة أحادي
- يمكن تسميم الذاكرة المؤقتة (ملاحظة دفاعية: مدخلات ثابتة، فحص ARP ديناميكي، مراقبة)

```bash
ip neigh show
arp -n
```

### الطبقة 3 — IP وICMP

**IPv4**

- حقول ترويسة ذات أهمية خاصة: Version، IHL، Total Length، TTL، Protocol، Source Address، Destination Address، Options
- بلا اتصال، تسليم بأفضل جهد
- التجزئة ممكنة (غالبًا تُتجنّب مع PMTUD)

**IPv6**

- عناوين 128 بت، ترويسة مبسّطة، ترويسات امتداد
- لا بث؛ يستخدم البث المتعدد واكتشاف الجيران (NDP) بدل ARP

**ICMP**

- التشخيص والإبلاغ عن الأخطاء (Echo Request/Reply، Destination Unreachable، Time Exceeded، …)
- يستخدمه `ping` و`traceroute`
- يمكن إساءة استخدامه للاستطلاع أو الأنفاق؛ غالبًا يُصفّى انتقائيًا

```bash
ping -c 3 8.8.8.8
traceroute example.com
```

### الطبقة 4 — TCP وUDP

**TCP (بروتوكول التحكم في النقل)**

- موجّه بالاتصال، موثوق، تدفق بايتات مرتب
- المنافذ تعرّف نقاط النهاية
- مصافحة ثلاثية: SYN → SYN-ACK → ACK
- أرقام التسلسل والإقرار، النافذة، الأعلام (SYN، ACK، FIN، RST، PSH، URG)
- التحكم في التدفق والازدحام
- الإنهاء: تبادل FIN/ACK أو RST

**UDP (بروتوكول مخطط بيانات المستخدم)**

- بلا اتصال، ترويسة دنيا (منافذ، طول، مجموع اختباري)
- لا موثوقية أو ترتيب أو تحكم ازدحام في البروتوكول نفسه
- مفضّل لاستعلامات DNS والوسائط الفورية وكثير من تصاميم الأنفاق/VPN حيث يتعامل التطبيق مع الموثوقية

```bash
ss -tuln
ss -tan
```

### بروتوكولات التطبيق والدعم

#### DNS (نظام أسماء النطاقات)

- يحل الأسماء ↔ العناوين (وأنواع سجلات أخرى)
- UDP/53 لمعظم الاستعلامات؛ TCP/53 لنقل المناطق والاستجابات الكبيرة
- محلّلات تكرارية مقابل موثوقة
- امتدادات الأمن: DNSSEC (أصالة/سلامة البيانات)؛ ما زال نصًا واضحًا إلى حد كبير دون DoT/DoH

#### DHCP

- إعداد المضيف الديناميكي (عنوان IP، القناع، البوابة، خوادم DNS، …)
- منافذ UDP 67 (خادم) / 68 (عميل)
- تسلسل Discovery → Offer → Request → Acknowledge
- خوادم DHCP المارقة خطر كلاسيكي في الشبكة المحلية

#### HTTP / HTTPS

- بروتوكول التطبيق للويب (وكثير من واجهات برمجة التطبيقات)
- HTTP/1.1: طلب/استجابة نصي، ترويسات، طرق (GET، POST، PUT، DELETE، …)
- HTTPS = HTTP فوق TLS (سرية، سلامة، مصادقة الخادم)
- HTTP/2 وHTTP/3 يقدمان تأطيرًا وتعددًا و(لـ HTTP/3) QUIC فوق UDP

يُغطى بعمق أكبر في الوحدة 06.

#### TLS (أمن طبقة النقل)

- يوفر التشفير والسلامة والمصادقة لتدفق بايتات (عادة تحت HTTP، SMTP، إلخ)
- المصافحة تتفاوض الإصدار ومجموعة التشفير والشهادات
- أفضل ممارسة حالية: TLS 1.2+ بتشفيرات قوية؛ TLS 1.0/1.1 مهجور

#### SSH (القشرة الآمنة)

- تسجيل دخول عن بُعد آمن وأنفاق
- يُغطى بالتفصيل في الوحدة 05

#### SMTP / IMAP / POP3

- نقل البريد والوصول
- تتوقع النشرات الحديثة STARTTLS أو TLS ضمني
- آليات المصادقة تختلف؛ AUTH النص الواضح مهجور

#### NTP

- مزامنة الساعة (UDP/123)
- مهم لارتباط السجلات والتحقق من الشهادات
- توجد متغيرات NTP مصادقة؛ كثير من النشرات ما زالت تعتمد على وقت غير مصادق

#### SNMP

- مراقبة وإدارة أجهزة الشبكة
- الإصدارات: v1/v2c (سلاسل المجتمع — ضعيفة)، v3 (أمن قائم على المستخدم)
- يجب تقييده ويفضّل الإصدار 3 فقط

#### بروتوكولات أخرى بارزة

| البروتوكول | المنفذ (شائع) | الدور |
|------------|---------------|-------|
| FTP | 21 (تحكم) | نقل ملفات (نص واضح؛ فضّل SFTP/FTPS) |
| SFTP | 22 (عبر SSH) | نقل ملفات آمن |
| RDP | 3389 | سطح مكتب بعيد (Windows) |
| SMB | 445 | مشاركة ملفات/طابعات (أنظمة Windows) |
| LDAP | 389 / 636 | وصول الدليل (636 = LDAPS) |
| Kerberos | 88 | مصادقة قائمة على التذاكر |
| Syslog | 514 (UDP تقليدي) | شحن السجلات |

## خصائص أمن البروتوكول (عرض ملخص)

| البروتوكول | السرية | السلامة | المصادقة (نموذجية) |
|------------|--------|---------|-------------------|
| HTTP | لا | لا | على مستوى التطبيق إن وُجدت |
| HTTPS (TLS) | نعم | نعم | الخادم (العميل اختياري) |
| Telnet | لا | لا | ضعيفة (كلمات مرور واضحة) |
| SSH | نعم | نعم | المضيف + المستخدم (مفاتيح/كلمات مرور) |
| DNS | لا (ما لم DoT/DoH/DNSSEC) | DNSSEC يوفر سلامة البيانات | محدودة |
| ARP | لا | لا | لا (ثقة رابط محلي) |

## أمثلة عملية

```bash
# مراقبة استخدام البروتوكول على مضيف
ss -tuln
ss -tan | head

# مسار حل DNS
dig example.com
dig +trace example.com

# فحص TLS سريع (إن توفر openssl)
openssl s_client -connect example.com:443 -servername example.com </dev/null 2>/dev/null | head -30
```

## أخطاء شائعة

| الخطأ | نهج أفضل |
|-------|----------|
| افتراض أن «منفذ مشفر» يعني أن التطبيق آمن | التشفير يحمي القناة؛ منطق التطبيق والمصادقة ما زالا مهمين |
| ترك بروتوكولات النص الواضح القديمة مفعّلة | عطّل Telnet، FTP، SNMPv1/v2c، الإدارة غير المصادقة |
| تجاهل DNS كاعتمادية حرجة | راقب واحمِ المحلّلات؛ فكّر في DNSSEC ونقل DNS مشفر |
| معاملة ICMP كضوضاء خالصة | مفيد للتشخيص ويمكن أن يحمل أيضًا قنوات سرية |

## أفضل الممارسات

- فضّل البروتوكولات ذات الحماية التشفيرية الحديثة (SSH، TLS 1.2+، HTTPS).
- عطّل أو قيّد خدمات النص الواضح المهجورة.
- وثّق البروتوكولات المطلوبة في كل شريحة شبكة.
- في المختبرات، تدرب على تحديد البروتوكولات من أرقام المنافذ ومن ترويسات الحزم.
- أبقِ معرفة البروتوكول محدّثة — الإصدارات الجديدة (HTTP/3، TLS 1.3، QUIC) تغيّر أنماط الحركة.

---

## تمرين عملي

1. اسرد المقابس المستمعة على مضيف مختبر وعيّن كلًا إلى بروتوكول/خدمة.
2. نفّذ بحث DNS بـ `dig` وحدّد نوع الاستعلام وسجلات الاستجابة.
3. التقط تبادل ARP قصيرًا وتبادل ICMP Echo في مختبر؛ لاحظ ترويسات Ethernet وIP.
4. قارن طلب HTTP نص واضح باتصال HTTPS باستخدام أداة مطور المتصفح أو `curl -v` (أهداف مختبر فقط).

---

## أسئلة المراجعة

1. أي مشكلة يحلها ARP، وفي أي طبقة يعمل؟
2. ما الفرق السلوكي الرئيسي بين TCP وUDP؟
3. لماذا يُفضَّل HTTPS على HTTP للبيانات الحساسة؟
4. أي بروتوكول مسؤول أساسًا عن حل الأسماء إلى عناوين؟
5. اذكر بروتوكولي إدارة أو مراقبة ومخاوف أمنية لكل منهما.

---

## ملخص

تعرّف البروتوكولات لغة اتصال الشبكة. إتقان بروتوكولات الطبقات 2–4 الرئيسية إضافة إلى DNS وHTTP/HTTPS وTLS وSSH يغطي غالبية عمل الحركة وتحليل الأمن. عيّن دائمًا بروتوكولًا إلى طبقته وخصائصه الأمنية والضوابط التي يمكنها حمايته أو مراقبته.
