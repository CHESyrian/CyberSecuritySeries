# 05 — SSH وTelnet

## مقدمة

الوصول عن بُعد لسطر الأوامر متطلب يومي لإدارة الأنظمة وعمل الأمن. يخدم هذا الغرض بروتوكولان تاريخيان مهمان: **Telnet** (نص واضح، مهجور للشبكات غير الموثوقة) و**SSH** (القشرة الآمنة — مشفر ومصادق). تشرح هذه الوحدة كليهما، وتؤكد لماذا Telnet غير آمن، وتغطي استخدام SSH العملي والمصادقة بالمفتاح والتصلب الأساسي.

---

## أهداف التعلم

- وصف بروتوكول Telnet ونواقصه الأمنية
- شرح أهداف أمن بروتوكول SSH وهندسته عالية المستوى
- استخدام SSH لتسجيل الدخول التفاعلي وتنفيذ الأوامر ونقل الملفات (SCP/SFTP)
- إعداد واستخدام المصادقة بالمفتاح العام
- تطبيق ممارسات تصلب خادم SSH الأساسية في مختبر
- التعرف على مخاطر SSH الشائعة (مفاتيح ضعيفة، إساءة توجيه الوكيل، إلخ)

---

## المفاهيم الأساسية

### 1. Telnet

- بروتوكول للتواصل النصي التفاعلي ثنائي الاتجاه (RFC 854 وما يتعلق).
- المنفذ الافتراضي **TCP 23**.
- **لا تشفير** — أسماء المستخدمين وكلمات المرور ومحتوى الجلسة تسير نصًا واضحًا.
- **لا حماية سلامة** — يمكن لمهاجم على المسار تعديل الجلسات.
- ما زال يُوجد أحيانًا على معدات قديمة ويجب معاملته كخطر عالٍ إذا كان مكشوفًا.

```bash
# مثال (المختبر فقط، ضد نظام تملكه)
telnet 192.0.2.10
```

**التوصية:** عطّل خوادم Telnet؛ استخدم SSH بدلًا منه. إذا كان جهاز يدعم Telnet فقط، اعزله على شبكة إدارة وفضّل مضيف قفز بـ SSH.

### 2. SSH — الأهداف والهندسة

يوفر SSH:

- السرية (تشفير)
- السلامة (كشف التلاعب)
- المصادقة (مفتاح مضيف الخادم + مصادقة المستخدم)
- توجيه اختياري (TCP، X11، الوكيل)

الإصدارات الرئيسية: SSH-2 هو المعيار الحالي (SSH-1 مهجور وغير آمن).

مكوّنات نموذجية:

| المكوّن | الدور |
|---------|-------|
| `sshd` | شيطان الخادم |
| `ssh` | العميل |
| `ssh-keygen` | توليد المفاتيح |
| `ssh-agent` / `ssh-add` | الاحتفاظ بالمفتاح في الذاكرة |
| `scp` / `sftp` | نقل الملفات فوق SSH |
| `~/.ssh/config` | إعداد العميل |
| `/etc/ssh/sshd_config` | إعداد الخادم |

المنفذ الافتراضي: **TCP 22** (يمكن تغييره؛ الغموض وحده ليس أمنًا).

### 3. مصادقة المضيف

عند الاتصال الأول يتلقى العميل **مفتاح مضيف** الخادم. يجب التحقق من البصمة خارج النطاق. الاتصالات اللاحقة تفحص المفتاح مقابل `~/.ssh/known_hosts`. مفتاح متغير ينتج تحذيرًا قويًا — حقق قبل القبول.

```bash
ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub
ssh-keygen -R hostname
```

### 4. طرق مصادقة المستخدم

1. **المصادقة بالمفتاح العام** — مفتاح خاص على العميل، مفتاح عام في `~/.ssh/authorized_keys` على الخادم.
2. **تفاعلي بلوحة المفاتيح / كلمة المرور** — مقبول عندما لم تُنشر المفاتيح بعد.
3. **قائم على الشهادة** (OpenSSH CA) — نمط مؤسسة قابل للتوسع.
4. **GSSAPI / Kerberos** — في بيئات منضمة إلى نطاق.

```bash
ssh-keygen -t ed25519 -C "lab-key" -f ~/.ssh/id_ed25519_lab
ssh-copy-id -i ~/.ssh/id_ed25519_lab.pub user@server
```

احمِ المفاتيح الخاصة بعبارة مرور وصلاحيات ملف مقيدة (`chmod 600`).

### 5. استخدام العميل العملي

```bash
ssh user@server.example.com
ssh -p 2222 user@server
ssh user@server "uptime; df -h"
ssh -v user@server
ssh -J jumpuser@jumphost targetuser@target
ssh -L 8080:localhost:80 user@server
scp file.txt user@server:/path/
sftp user@server
```

### 6. تصلب الخادم الأساسي (إرشاد المختبر)

توجيهات نموذجية في `/etc/ssh/sshd_config`:

```
PermitRootLogin no
PasswordAuthentication no
PubkeyAuthentication yes
PermitEmptyPasswords no
X11Forwarding no
AllowUsers alice bob
MaxAuthTries 3
```

```bash
sudo sshd -t
sudo systemctl reload sshd
```

## أخطاء شائعة

| الخطأ | النتيجة |
|-------|---------|
| ترك Telnet مفعّلاً | تعرض الاعتمادات والجلسة |
| مفاتيح خاصة غير محمية | سرقة المفتاح تؤدي لاختراق الحساب |
| قبول مفاتيح مضيف متغيرة بشكل أعمى | MITM محتمل |
| تسجيل دخول root بكلمة مرور | سطح هجوم واسع |

## أفضل الممارسات

- فضّل المصادقة بالمفتاح؛ عطّل مصادقة كلمة المرور بمجرد عمل المفاتيح.
- استخدم مفاتيح ed25519 أو RSA قوية.
- قيّد `sshd` بـ AllowUsers/AllowGroups وACLs الشبكة.
- عامل مضيفي قفز SSH كأصول عالية القيمة.
- سجّل وراقب نجاح/فشل المصادقة.

---

## تمرين عملي

1. ولّد زوج مفاتيح ed25519 وأعد تسجيل الدخول بالمفتاح إلى خادم مختبر.
2. عطّل مصادقة كلمة المرور على `sshd` المختبر وتحقق من فشل محاولات كلمة المرور.
3. استخدم `scp` أو `sftp` لنقل ملف.
4. افحص بصمة مفتاح مضيف الخادم.

---

## أسئلة المراجعة

1. لماذا يُعتبر Telnet غير آمن على الشبكات غير الموثوقة؟
2. أي خطوتي مصادقة يؤديهما SSH؟
3. أي ملف على الخادم يسرد المفاتيح العامة المسموحة لمستخدم؟
4. ما الغرض من ملف `known_hosts`؟
5. اذكر ثلاثة إعدادات تصلب مفيدة لـ `sshd_config`.

---

## ملخص

ينقل Telnet الجلسات نصًا واضحًا ويجب عدم استخدامه على الشبكات غير الموثوقة. يوفر SSH وصولًا عن بُعد مشفرًا ومصادقًا وهو الأداة القياسية للإدارة الآمنة.
