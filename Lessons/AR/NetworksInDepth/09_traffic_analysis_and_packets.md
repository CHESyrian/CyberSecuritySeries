# 09 — تحليل الحركة والحزم

## مقدمة

تحوّل الرؤية على مستوى الحزمة معرفة البروتوكول المجردة إلى أدلة ملموسة. يُستخدم تحليل الحركة لاستكشاف الأخطاء ومراقبة الأداء وكشف التهديدات والاستجابة للحوادث. تغطي هذه الوحدة بنية الحزمة وأدوات الالتقاط وسير عمل التحليل الأساسي والمتطلب الصارم للعمل فقط في بيئات مصرح بها.

---

## أهداف التعلم

- وصف البنية المتداخلة لحزمة Ethernet + IP + TCP/UDP نموذجية
- التقاط الحركة بأمان بـ `tcpdump` وفحصها بـ Wireshark أو `tshark`
- تطبيق مرشحات العرض والالتقاط بفعالية
- استخراج الحقول عالية القيمة (العناوين، المنافذ، الأعلام، الحمولات عند الاقتضاء)
- التعرف على الأنماط الشائعة (المصافحات، استعلامات DNS، TLS ClientHello، الاعتمادات النص الواضح)
- اتباع منهجية التقاط أخلاقية وبأقل تأثير في إعدادات المختبر

---

## المفاهيم الأساسية

### 1. بنية الحزمة (مراجعة التغليف)

حزمة IPv4 TCP شائعة على Ethernet:

```
[ ترويسة Ethernet ]
    MAC الوجهة | MAC المصدر | EtherType (0x0800)
[ ترويسة IPv4 ]
    Version، IHL، TOS/DSCP، Total Length، ID، Flags، Fragment Offset،
    TTL، Protocol (6=TCP)، Header Checksum، Src IP، Dst IP، Options
[ ترويسة TCP ]
    منفذ المصدر، منفذ الوجهة، Seq، Ack، Data Offset، Flags، Window،
    Checksum، Urg Ptr، Options
[ الحمولة ]
    بيانات التطبيق (HTTP، سجلات TLS، …)
[ Ethernet FCS ]
```

يستبدل UDP ترويسة TCP بترويسة UDP أقصر (منافذ، طول، مجموع اختباري).

### 2. نقاط الالتقاط والرؤية

| موقع الالتقاط | ما تراه عادة |
|---------------|-------------|
| واجهة المضيف | حركة من/إلى ذلك المضيف (وأحيانًا البث/البث المتعدد) |
| منفذ SPAN/مرآة المبدل | نسخة من حركة منافذ أو VLANs محددة |
| TAP شبكة | نسخة سلبية لرابط |
| مستشعر جدار نار / IDS | حركة تعبر ذلك الحد |
| سجلات تدفق VPC السحابة | بيانات وصفية (ليست حزمًا كاملة) في كثير من العروض |

يحد التشفير (TLS، VPN، SSH) من رؤية الحمولة؛ البيانات الوصفية (العناوين، المنافذ، الأحجام، التوقيت، حقول مصافحة TLS) غالبًا تبقى مفيدة.

### 3. الأدوات

**tcpdump** — التقاط سطر أوامر وتحليل خفيف (libpcap).

```bash
sudo tcpdump -i eth0 -w capture.pcap
sudo tcpdump -i eth0 -nn tcp port 80
tcpdump -r capture.pcap -nn
```

**Wireshark / tshark** — تحليل كامل الميزات (واجهة رسومية وسطر أوامر).

- مرشحات العرض (Wireshark) مقابل مرشحات الالتقاط (صيغة pcap/BPF — لغتان مختلفتان).
- متابعة تدفق TCP، Expert Info، محلّلات البروتوكول، تصدير الكائنات.

**أدوات أخرى مفيدة:** `ss`، `netstat`، `tshark`، Zeek / Suricata، سجلات تدفق السحابة، NetFlow/IPFIX.

### 4. مرشحات الالتقاط (BPF) مقابل مرشحات العرض

**مرشح الالتقاط** (يحد ما يُخزَّن — كفء):

```
host 192.0.2.10
net 192.0.2.0/24
port 53
tcp port 443
icmp
```

**مرشح العرض** (Wireshark — بعد الالتقاط):

```
ip.addr == 192.0.2.10
tcp.port == 443
http.request.method == "GET"
dns.qry.name contains "example"
tls.handshake.type == 1
```

### 5. سير عمل التحليل (عملي)

1. **عرّف السؤال** — فشل اتصال؟ نقل بطيء؟ سر نص واضح مشتبه؟ سلوك DNS؟
2. **اختر نقطة الالتقاط والمرشح** — قلّل الحجم وتأثير الخصوصية.
3. **التقط لفترة محدودة** أو حتى يحدث الحدث محل الاهتمام.
4. **افحص البيانات الوصفية أولاً** — المحادثات، نقاط النهاية، المنافذ، الأحجام، التوقيت.
5. **تعمّق في تدفقات مختارة** — مصافحة TCP، إعادة الإرسال، ترويسات التطبيق.
6. **وثّق النتائج** واحذف التقاطات تحتوي بيانات حساسة بأمان عندما لم تعد مطلوبة.

### 6. أنماط تستحق التعرف

| النمط | ما تبحث عنه |
|-------|-------------|
| مصافحة TCP ثلاثية | SYN، SYN-ACK، ACK بأرقام seq/ack متطابقة |
| إنهاء TCP | تسلسل FIN/ACK أو RST |
| استعلام/استجابة DNS | UDP/53، اسم الاستعلام، رموز الاستجابة وRRs |
| TLS ClientHello / ServerHello | SNI، مجموعات التشفير، رسائل الشهادة |
| سطر طلب HTTP | الطريقة، المسار، ترويسة Host (نص واضح فقط) |
| طلب/رد ARP | Who-has / is-at على الشريحة المحلية |
| إعادة الإرسال / ACKs مكررة | مشاكل أداء أو فقدان |

### 7. الأخلاق والقانون وانضباط المختبر

- التقط **فقط** على الشبكات والأنظمة التي تملكها أو لديك لها **تفويض كتابي صريح**.
- فضّل شبكات المختبر المعزولة والحركة الاصطناعية.
- عامل التقاطات كمادة حساسة: قد تحتوي اعتمادات أو بيانات شخصية أو رموز جلسة.
- قلّل الاحتفاظ؛ شفّر التخزين إن كان الاحتفاظ مطلوبًا.
- اعتراض الاتصالات دون تفويض غير قانوني في معظم الولايات القضائية.

## أمثلة عملية

```bash
sudo tcpdump -i eth0 -nn -c 50 tcp port 80 -w http-lab.pcap
sudo tcpdump -i eth0 -nn port 53 -c 20
tshark -r http-lab.pcap -q -z endpoints
tshark -r http-lab.pcap -Y "http.request" -T fields -e http.host -e http.request.uri
```

سير عمل واجهة Wireshark الرسومية:

1. افتح الـ pcap.
2. استخدم مرشح العرض `tcp.flags.syn == 1 and tcp.flags.ack == 0` لإيجاد بدايات الاتصال.
3. انقر يمينًا على حزمة → Follow → TCP Stream.
4. افحص قوائم Statistics (Conversations، Endpoints، Protocol Hierarchy).

## أخطاء شائعة

| الخطأ | النتيجة |
|-------|---------|
| الالتقاط دون مرشح على رابط مزدحم | ملفات ضخمة، أحداث فائتة، جمع خصوصية زائد |
| الخلط بين مرشحات الالتقاط ومرشحات العرض | التقاطات فارغة أو نتائج غير متوقعة |
| تحليل حركة إنتاج دون تفويض | انتهاك قانوني وأخلاقي |
| ترك التقاطات باعتمادات على تخزين مشترك | خرق بيانات ثانوي |
| النظر فقط إلى الحمولة وتجاهل التوقيت/الحجم | أنماط C2 أو تسريب فائتة |

## أفضل الممارسات

- ابدأ دائمًا بنطاق تفويض مكتوب أو مفهوم بوضوح.
- استخدم أضيق مرشح ما زال يجيب على السؤال.
- فضّل تحليل البيانات الوصفية والمصافحة عندما تكون الحمولات مشفرة.
- اربط بيانات الحزم بسجلات المضيف وجدار النار ومعلومات العملية.
- وثّق بيئة الالتقاط (الواجهة، المرشح، نافذة الوقت، الغرض).
- في التدريب، استخدم pcaps عامة أو حركة مختبر مولّدة ذاتيًا بدل بيانات مستخدم حقيقية.

---

## تمرين عملي

1. ولّد بضعة استعلامات DNS وطلب HTTP على شبكة مختبر؛ التقطها بـ `tcpdump` باستخدام مرشحات مناسبة.
2. افتح التقاط في Wireshark أو `tshark` وحدّد ترويسات Ethernet وIP والنقل لحزمة واحدة.
3. تابع تدفق TCP لتبادل نص واضح وحدد سطر الطلب أو اسم استعلام DNS.
4. اكتب مرشح عرض يُظهر فقط استجابات DNS التي تحتوي اسمًا محددًا.
5. اسرد المحادثات (أزواج IP) الموجودة في التقاط والمنافذ المعنية.

## أسئلة المراجعة

1. ما المعلومات الموجودة في خماسية حزمة TCP؟
2. لماذا قد تختار مرشح التقاط بدل التقاط كل شيء والتصفية لاحقًا؟
3. ما الفرق بين مرشح التقاط ومرشح عرض Wireshark؟
4. اذكر ثلاثة حقول ما زال بإمكانك ملاحظتها عندما تكون بيانات التطبيق محمية بـ TLS.
5. ما القاعدة الأخلاقية الأساسية لالتقاط الحزم؟

## ملخص

يربط تحليل الحركة نظرية البروتوكول بالسلوك القابل للملاحظة على السلك. فهم بنية الحزمة واستخدام مرشحات الالتقاط والعرض بشكل صحيح واتباع سير عمل منضبط ومصرح يتيح استكشاف أخطاء فعالًا وتحقيقًا دفاعيًا. يحد التشفير من رؤية الحمولة لكنه يترك بيانات وصفية قيمة؛ يكمل سياق المضيف والشبكة الصورة.

---

## المصادر

- وثائق tcpdump / libpcap
- دليل مستخدم Wireshark ومرجع مرشح العرض
- RFCs لـ IP وTCP وUDP (تنسيقات الترويسة)
- السياسة القانونية والتنظيمية حول المراقبة (الولاية القضائية المحلية وقواعد صاحب العمل)
